冻结对照是上一轮集成通过的产品：相位配对默认开启。B 使用相同的原生后台、WASM、字体和主进程，仅重建当前渲染客户端。Apple M2 Pro / 16 GiB，原件为 118,272,240 字节的《拓扑素材.sketch》。单个光栅 owner；原有 64 命令切片、高水位、显存准入和真实完成回执保持不变。

1. 从原件指定相机抓取六个已验证的密集帧包；从桌面重新捕获 3200% 请求和实际源描述符。高倍的原生选项不增加 dense paint。复建独立回放时仅移除上一个 worker 的 frameResources 命中回执。完整桌面不改任何请求。高倍四个屏内块与两个边缘预取块分别统计。
2. 查因轮记录实际高水位等待、每个资源准入、阻塞原因、异步完成观察、提交、维护的同步前段；跟踪滤镜表面的实际分配、复用、借用期限与最后释放。后台 fence 会重叠，禁止将其耗时累加为阻塞；graph 减 checkpoint 也不是纯 JS CPU 或 GPU shader 时间。记录每次双相位批次的实际写区和输出矩形。计时查询会改变配对准入，主实验不打开 GPU timestamp queries。
3. 设备对照：每个样本 A/B 单独设备，两臂先预热；ABBA BAAB，各四次，不读回；开始前排空，记录 render 返回及其后队列真正完成，给出每块中位数之和。单独截取最终 RGBA32F，比较每个通道的 IEEE 位。探索性候选不能只凭显存、像素数或 draw 数通过。端到端改善和资源峰值一起判断；未获证实的改变不默认启用。
4. 桌面：每臂两个全新 profile，ABBA，固定原件、窗口、同一相机。计时不截图；区分手势结束/最后真实输入到整屏 ready、原生编包与 GPU 诊断。另开两个工作区回放相同相机，比较清晰后原生画布的 RGBA，另报窗口裁区。没有从单个样本推算所有场景的加速。

生产选择分四步：A 是上轮产品；B 只改 GPU（包含候选跨空位合批）；C 默认关闭跨空位合批，加入原生曲线细分的保守快速判定；最终产品再加入停稳时对已经有完整显示画面的高倍源视口的优先级。分别记录每一对的默认值。GPU 固定包实验的 B 仍指第一步的组合；独立原生产物日志的 A/B 则分别指旧版和该组文件所测的候选，均由产物 SHA 定义。

高倍原生实验每臂三次，ABBAAB，独立进程；载入完全相同的源快照，再提交相同相机的六个原始选项。端到端桌面观察另行使用真实手势，不能把独立冷编包时间直接加到桌面总时间。不同进程的 frame resourceScope 必须不同；对照同一版本的两个独立进程也是如此。比较除该会话标识外的所有元数据、原始几何、资源载荷字节和完整解码场景。

CPU 比较仍使用已共享的单帧准备作为对照。沿用上一轮相同的 Rust 计时探针和 117 的真实导入文件、字体、50% 全页相机。每档新进程 ABBA，每次一冷两暖；准备和整帧取暖帧中位，Darwin RSS 和 physical footprint 取各进程高水位的中位。读回、16 位 HDR PNG 和 CPU/WASM 针对性 QA 独立执行。移动预览、停稳精修、固定相机和单张纹理的不同指标始终分开。
