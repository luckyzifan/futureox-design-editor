# Shared selection commands: local v1 Core contract (stage-two candidate)

Status: this independent stage-two candidate implements one Core selection-command contract for the four existing methods and matching UI routes. Verification is recorded separately; source availability alone is not a passing test or an integrated release. The previously integrated stage-one implementation retained four UI/MCP differences. No new endpoints, compatibility selectors, backend, authentication or collaboration merge are introduced. The abandoned versioned-endpoint draft is superseded by this document.

## Existing implementation boundary

UI commands and automation draft handlers share affine, arrangement and child-list mechanics. UI still commits as user; automation retains schema/permission checks, isolated staging, document/session/revision fences and one authoritative Editor/Rust commit. Private committed-edit receipts preserve exact accepted owner/snapshot/history facts across synchronous supersession. Receipts grant no mutation or replay authority.

The four original differential fixtures remain as baseline negative controls: curve geometry versus nominal-box alignment; curve group dimensions/origin; section ungroup support; selection-frame fill/clipping/blend defaults. Candidate tests compare complete authored document state, selection and native undo/redo, not two different expected outcomes. Historical stage-one expected-difference tests are retained in the verification evidence, not mislabeled as parity passes.

## Shared command rules and explicit remaining limits

The existing node.align, node.distribute, node.group and node.ungroup methods and corresponding UI routes use commands/selection-command.ts. Do not invent Figma aliases, new versioned endpoints or historical compatibility routing for an unreleased local v1 application.

- Shared admission precedes plan application and geometry measurement. Preserve explicit missing/locked/instance/auto-layout restrictions; reject mixed invalid targets atomically instead of silently editing a subset. Protocol scopes, batch wrapper/leaf authorization, budgets, fences, source provenance and receipt handling remain adapter responsibilities. All nodes must belong to one page; wrapping requires one immediate parent. Selected ancestor roots cover their descendants, and ordering follows scene preorder rather than request order.
- Single selection aligns in parent-local coordinates; multiple same-page selections use world geometry. Ordinary non-path primitives, text boxes, frames and sections use their authored boxes; paths/networks/text paths/path offsets use native geometry bounds, with no nominal fallback on failure. Ordinary groups union all child geometry, including hidden descendants. Explicit hidden targets remain measurable. Hidden-node treatment, stroke/effect exclusion and ambiguous distribution behavior are explicit Core conventions, not certified Figma algorithms.
- Selection wrapping uses shared parent-local geometry, preserves child world transforms and selected sibling order, and uses transparent, unclipped, pass-through defaults for both group and selection-frame. Empty node.create frame remains a different intent with its existing factory defaults. A wrapper is inserted at the first selected sibling and preserves selected sibling order; noncontiguous grouping does not promise unchanged overlap against intervening siblings. Reparented child constraint reference dimensions reset like Editor.reparentMany, so native layout adopts the new parent without applying a resize delta from the old one.
- Unwrap ordinary group/frame/section/boolean containers one level, retaining child transforms and authored styles. Components, component sets, instances and instance-internal topology cannot be wrapped or unwrapped by these methods; whole-instance alignment and native captured transform overrides remain separate allowed intents. Direct mask scope is released without disturbing nested mask scopes. Container effects/clipping removal is not promised to preserve pixels.
- Auto-layout flow-child positioning rejects with auto_layout_position; absolute children remain positionable. Wrap/unwrap of active auto-layout topology rejects with unsupported_layout_topology. Two-object distribution is an unchanged result with no history; three or more non-overlapping intervals use equal edge gaps and fixed outer objects. Overlap/containment rejects with unsupported_distribution_geometry. These rejected cases remain pending, not successful editing.
- Geometry preparation does not invoke whole-document layout. Native bounds receive private per-measurement shallow records, never mutable draft nodes as WeakMap keys. A first batch operation may use the current normalized root; after an earlier operation, arrangement, wrapping AND unwrapping reject selected subtrees or ancestors with boolean/component/instance/text/layout/binding/constraint/non-fixed-sizing dependencies with unsupported_derived_batch_geometry. Simple current networks remain measurable using new keys. The internal freshness fact is not accepted in request JSON and grants no authority. Unwrap must perform this check before lifting child transforms or resetting constraint references: resizing a constrained wrapper earlier in the same draft must not discard its unresolved displacement. Separate normalized commits remain supported. Full derived-batch resolution remains pending, with separate correctness/performance evidence.

Verification requires the original four differential fixtures to produce truly equal geometry/topology/defaults, plus matching undo/redo, complete rollback on invalid input, permissions/fences, mask/instance/layout rules, batch geometry freshness and receipt supersession. Runtime source identity and matching WASM must be verified. GUI/GPU/socket/external-client acceptance remains separate. Shift align-selection-to-parent, layout-aware topology, overlapping distribution, MCP mask/boolean creation and broader Scale/vector gesture parity are not introduced here.

## Official comparison boundary

Figma documents parent/sibling alignment and equal edge spacing with fixed outer objects, but does not publish the complete curve/stroke/rotated/overlapping selection algorithm. Its grouping API preserves absolute positions and disallows reparenting instance children. Ungroup moves children out and removes the container; components and instances cannot be directly ungrouped. Its boolean tutorial explicitly permits ungrouping boolean groups back into the original objects. Empty frame factory defaults are not evidence for selection-frame defaults.
