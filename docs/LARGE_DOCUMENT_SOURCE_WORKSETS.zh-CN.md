# 大文档源文件与页面工作集

Electron 的普通打开入口和“打开大型 JSON / Sketch…”共用源文件存储适配器。超过 64 MiB 的 JSON / Sketch 在索引后自动载入第一画板，直接使用普通 App 的工具栏、Layers、Canvas、Inspector；完整页面和其他画板由同一侧栏导航。原独立源文件画布和 JSON 编辑对话框已移除。原文件不被覆盖；缓存和导出目标由主进程授权，渲染进程只收到会话身份、分页列表和有界片段。源文件的固定 4 GiB 上限已移除，当前容量由实际存储卷与安全偏移范围约束；这不等于完整文档能同时进入 WASM/JS/GPU 内存。

## 数据路径

1. 原生后台在独立、有界的大文件 blocking 通道中复制源文件并核对 SHA-256。JSON 按 64 KiB 缓冲扫描 UTF-8、语法和对象位置；Sketch 逐成员解压并检查名称、数量、压缩比、实际长度和 CRC。完整展开内容保留在磁盘；索引和导出不生成原始巨型页面的 JS 字符串或 `serde_json::Value`。进入画布时另按有界窗口转换场景。
2. Rust 保存精简对象行和磁盘元数据位置，列表每次最多 200 行。选中对象才读取属性；大字段和子树保留源字节。源位置使用 u64，原生端读取存储卷容量，并在复制/展开前检查实际可用空间；ordinary document、WASM 和 GPU 工作预算仍独立。
3. 属性修改使用预期版本和片段 hash 校验。源 piece table 保留原区间，新增片段追加磁盘；撤销历史保存区间描述。发布日志前失败保持旧版本，发布后的不确定结果必须查询会话，不自动重放。
4. 页面工作区通过现有 Sketch codec / shared Document 构造工作集，直接使用既有 Editor、Graph、Canvas、Layers、Inspector 和 Rust/WASM。可选择完整页面或展开后选择画板；普通 FD 自动保存器不会收到局部源文档。主场景通过带版本与 SHA-256 的 512 KiB 分块传输，并继续受原有 live Document 容量准入。不能准入的页面须选更小画板，不截断图层。保存发送已修改字段；完整双精度几何缩放经严格比较可改用缩放参数，原生端重验并执行。未加载内容不会被当成已删除节点。JSON 属性和旧局部子树编辑仍可使用。
5. 完整导出逐段读取原文与新增区间。Sketch 中未改二进制成员沿用原 ZIP 数据；源成员 hash 在导出前复查。导出先捕获不可变源区间/增量快照并释放会话锁，导出期间可读取同会话；成功只标记实际导出的版本。输出先写临时文件，再原子发布到一个新的目标文件。原文件、未加载字段及无关成员均保留。

## 独立限制

| 项目 | 限制 |
| --- | --- |
| 源文件 / Sketch 所有展开成员总和 | 实际存储卷容量及安全源偏移上界；分配前另检查可用空间 |
| 可索引对象 | 1,000,000 |
| 源嵌套深度 / 单键 | 128 / 16 KiB |
| 一次源片段读取 | 4 MiB |
| 属性 / 单次修改 DTO、旧局部子树 DTO | 2 MiB |
| 主画布场景 DTO | 当前会话 documentCapacity；512 KiB 分块并核对完整 SHA-256 |
| 单次 Sketch 源转换窗口 | 每成员 64 MiB，成员合计 96 MiB；仍受场景准入限制 |
| Sketch 画布图片工作集 | 16 MiB，另受现有 codec 准入约束 |
| 列表 / 源撤销历史 | 最多 200 行 / 32 次 |
| 父子与短名称缓存 / 近期属性 LRU | 全部索引合计低于 64 MiB / 8 MiB、最多 16 条 |

超限时选择更小对象或明确拒绝，不通过截断内容生成导出。源属性与有界子树接口继续由原生存储层提供；普通工作台的 Sketch 页面提交目前支持已建模的现有图层属性，尚未承诺所有结构编辑可以保存。已有源路径的控制点增删、重排在没有可靠源点身份映射时拒绝，保留草稿；控制点坐标修改转换回原始 Sketch 坐标单位，保留未改字段和未启用控制柄。任意单个 4 GiB 字符串的直接文本编辑、全文件 Monaco model、浏览器 OPFS 适配器、完整大文档 live scene 和全图 GPU 渲染尚未实现。一般 JSON 数据可以编辑属性，只有满足共享设计结构的节点才能进入画布。

缓存保留供下次以相同原始内容恢复；它与源文件另存的交付语义不同。长期追加缓存的自动压缩/清理尚未提供，磁盘不足会报错并保留已经发布的版本。

本轮来源、4 GiB 实测、真实拓扑文件及 GUI 结果见[验证记录](../testing/verification-large-document-4gib-20261023/README.md)。CPU 文件链路通过不能替代整机交互、整图像素或 GPU 性能验收。

主画布与双精度路径重构的后续实测见[工作集渲染验证](../testing/verification-vector-geometry-20261023/README.md)。页面在 WASM 准备阶段失败时，恢复原画布的原生保存基线；原画布仍可继续保存。组件实例的宽高/变换覆盖只允许与同次根属性修改一致，组件身份及子节点覆盖保持原约束。新增普通源属性以有界字段追加写入，并重新流式验证、建立索引后发布，不重写或丢弃省略的大型路径字段。

## 长任务调度

Tokio 保留 2 个异步线程，blocking 池设为 4：最多 1 个普通业务任务、1 个大文件长任务，以及 stdio/解析所需位置。大文件通道最多接受 2 个长请求（运行与排队合计），全局仍最多 8 个业务请求并保留字节准入。普通写入维持自身 FIFO。

大文件 IPC 不占用 Electron 普通文件操作锁，而由同一窗口的大文件会话单独串行授权。小片段读取在普通通道执行；遇到源修改锁时立即返回忙，避免占住普通保存。进度直接读取独立的小状态与字节计数，取消仍是运行时控制请求。

桌面传输可请求 `desktopScheduling` 排队/执行回执。未获后台准入、排队、开始执行分别计时：后台明确排队后最多等待 10 分钟，开始执行后才使用普通 30 秒或大文件 10 分钟期限。回执不代表提交；断连后的写入结果仍按不确定结果处理，不能自动重试。

索引缓存依源版本刷新，长名称搜索回退到完整名称，不截断匹配；属性 LRU 以会话身份、源版本、对象键为键。增加并行的是两个业务通道，没有并行解压整个源文件或增加画布 GPU 并发。

## 双精度渲染路径与编辑网络

共享文档 schema 16 增加 `vectorGeometry`：f64 的 move/line/quad/cubic/close，独立填充与描边路径。它与 `network` 互斥；曲线通过既有 CPU/GPU、命中检测、布局、历史和导出链路。每节点最多 131072 个渲染命令，整份场景仍受原有字节/节点/路径/GPU 准入。控制点编辑按需构造原有的有界网络，10000 顶点和 20000 边的编辑准入没有扩大。没有引入位图替代、f32 文档坐标或降低效果精度。

Sketch 大顺序路径直接保留曲线次序；大布尔组转换成每步至多 64 输入的既有运算树，源转换最多 4096 个操作数。兼容导出验证中间节点仍为纯几何组合，再恢复源层级。不可表达的中间组编辑明确拒绝，不静默丢弃。源渐变中超范围的轴向垂直偏移，仅在可证明不参与线性采样时消去，原始锚点由既有格式元数据保留。

FIG 二进制网络和预计算路径统一经过 Rust 解码，网页 Worker 初始化同一 WASM。严格核对长度、索引、区域循环及有限值；切线按端点相对位移解释，按实际尺寸与 normalizedSize 的比例转换。源二进制 f32 值解码后用 f64 计算，不做十进制清理或再次 f32 量化。独立区域样式、混合区域填充等未完整支持语义仍需明确报告/拒绝，不能当作完整 Figma 兼容证明。

架构与 FIG 字段参考 Desigma `bb09ba87b1b7e7246b5dfbf916d75e3f12abe870`。该版本没有 Sketch 导入器；Sketch 使用本项目 codec。许可证说明见根目录 THIRD_PARTY_NOTICES.md。

## 普通工作台集成（2026-10-25）

源画板通过同一个 App 组件显示，但存储 owner 与整文档 FD 会话隔离。它不会进入普通 SQLite/IndexedDB 自动保存、恢复文件或启动缩略图保存。保存通过源 revision CAS 写回缓存；完整导出仍流式包含未载入成员。自动首画板载入完成后再刷新侧栏，避免并发占用原生源操作通道。

真实拓扑文件自动进入普通画板、三组素材编辑/撤销/重做/保存/完整导出/新实例重开已通过；64 个归档成员中 63 个字节一致，变化页仅有预期的三处名称和三处透明度变化。记录见 [工作台与交互验证](../testing/verification-drag-response-20261024/WORKLOG.md)。这不证明全面 Sketch 语义支持、运动无模糊或完整 G2/G5；这些仍未通过。
