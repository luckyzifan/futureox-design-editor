# 贡献与测试要求

运行命令、依赖和隔离参数见[本地测试使用方式](../testing/README.md)。涉及渲染、画布交互或性能的改动，按[渲染优先验收规范](RENDERING_FIRST_ENGINEERING_CONTRACT.zh-CN.md)选择需要实测的门槛。

## 回归用例

- 写明问题、影响范围、可观察的预期结果和最小输入。对修复使用同一夹具、依赖和断言，让旧版在预期断言处失败，候选通过。故障注入可以作为负对照。
- 覆盖改动实际经过的入口。渲染、保存、撤销、权限及异步生命周期变更，按影响验证取消、失败、过期结果、重复提交和最终状态。
- 验证精确错误及失败后的状态。等待异步回调须有截止时间。执行空集合检查前确认存在可用样本。结构检查和替身各自承担相应断言，并在结论中标明边界。
- 必需产品路径缺输入、命令非零、超时、空套件或全部跳过时，结果为失败、受阻或未运行。可选语料显式记录跳过原因。保留具体失败以及 Rust 的 ignored、脚本未选择的范围。
- 优先使用有来源的最小原创夹具。提供固定期望时，记录金图或参考实现的来源、版本、精度和容差。用例从已维护的测试路径读取固定输入。个人或授权范围有限的样本由运行者显式提供。

## 确认证据边界

| 层级 | 结论可覆盖的路径 |
| --- | --- |
| 静态、纯逻辑、jsdom、宿主替身 | 类型、结构、状态事务、DOM 或 IPC 回调的具体断言 |
| Rust/WASM、真实 SQLite 或 sidecar | 实际执行的文档、CPU、文件和本地持久化操作。前端引用 Rust 修复前重建对应产物 |
| 内存 MCP、真实 socket、外部客户端 | 分别记录协议请求、OS 传输和应用授权／外部客户端实际接入的结果 |
| Software GPU、hardware GPU、GUI、打包 | 分别记录实际驱动、像素或呈现、用户输入和已加载包身份。按平台报告 |
| 性能 | 同输入、同配置、已预热的成对对照。说明样本、工作量、资源峰值和计时起止。提交 ACK、GPU 完成和可见画面采用各自的证据 |

## 结论与测试产物

- PR 写清源码版本、是否有未提交变更、完整命令、运行平台和工具链、被加载产物及夹具来源。报告通过、失败、跳过、受阻和未运行，附对应原因与失败断言。运行级模板见[验证结论](verification/README.md)。
- 需要复跑的内容保留为执行代码、最小夹具和 Markdown 结论。测试数量、套件数量、断言数量和覆盖率分别报告。
- 临时工作树、安装包副本、隔离 profile 与中间文件使用本轮临时目录。调试原始输出时显式写入被忽略的 `test-results/<run>/`，在 Markdown 记下所需指标、哈希和重跑方式，复核后清理原始输出。
- 清理只处理该次测试创建的产物。确认前台测试和子进程已退出，按 Git 登记注销工作树，再删除运行目录。含未提交源码改动的历史副本先保存可重放的差异。真实用户工作区、产品 SQLite 和原始设计文件具有各自的生命周期。
