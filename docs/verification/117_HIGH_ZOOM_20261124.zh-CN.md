# 117.sketch 高倍缩放和画板交互复测

2026-11-24，Apple M2 Pro，16 GiB，macOS 26.3，Electron 44.7.0，Metal WebGPU，DPR 2。基线与最终构建均使用当前工作区的默认 release 配置和独立桌面配置目录。`117.sketch` 经产品文件选择器导入后为 752 个节点，SHA-256 为 `d494693eadf269e7fa29e4cc56e893f5890c02f4d96f4561065c851818a85d70`。

## 高倍精修

以下为真实窗口从输入倍率到目标相机、修订、设备密度和 GPU 呈现均就绪的单次实测。800% 对应 16 倍设备尺度，3200% 对应 64 倍。计时包含倍率控件操作和最多约 140 毫秒的状态采样间隔。

| 117 实际视口 | 基线 | 最终构建 |
| --- | ---: | ---: |
| 默认窗口到 800% | 52.43 秒 | 4.58 秒 |
| 默认窗口到 3200% | 291.25 秒 | 5.95 秒 |
| 1728 × 997 窗口到 3200% | 60 秒时仍显示上一倍率，174.30 秒报 GPU 表面预算错误 | 5.69 秒，完整就绪 |
| 大窗口 3200% 已完成瓦片的工作纹理峰值 | 1.74 GB | 0.88 GB |

在大窗口，原始设备尺度为 64。文字的 15 文档像素投影放大到 960 设备像素，三个盒式核的半径为 479、479、480。旧路径在水平、垂直各三次的滤镜中对每个输出像素重复读邻域。同一块瓦片还含有独立的背景图片高斯模糊。扩大单凸纯色椭圆的低密度试验只覆盖另一类输入。

另一个独立故障出现在底部五块瓦片。去掉文字投影仍能复现编译拒绝。逐层对照定位到了不透明矢量图层“矩形 5”的背景模糊。该次相机中，形状边线落在整数设备像素边界，瓦片内既有完全覆盖像素也有未覆盖像素。旧证明只认可一整块覆盖恒定的区域，因而为没有可见贡献的背景模糊申请了超限表面。

当前 Rust 编译器验证这类不透明覆盖的每条相关边，并为符合条件的独立实色投影从目标瓦片反推六次滤镜的输入区域。GPU 使用现有精确前缀和计算原始设备像素上的 alpha 或 RGBA 均值。每次滤镜的系数、轴序、透明边界和舍入边界均经过检查。半透明填充、斜边、分数边界、偏移投影和低倍率交互均有对应的回退或负例检查。

大窗口记录到的最长 GPU 队列等待由 11.69 秒降到 0.48 秒。另一次开启 GPU 时间戳的真实窗口回放记录了 4,640 个 pass，3200% 在 4.27 秒精确就绪，设备丢失事件为零。倍率菜单在 3200% 与 100%、200%、300%、400%、500% 之间往返，11 次目标倍率切换均完成目标相机和原生密度的就绪断言。3200% 下的空格拖动画布及反向平移均恢复了正确相机。输入 3200% 后约 120 ms 即反向输入 100%，最终构建约 0.35 秒回到清晰画面，基线两次为 8.71 和 8.96 秒。

## 像素对照

默认窗口的参考图取自原始基线实际完成的 GPU 帧。大窗口的基线无法产出整张图，参考构建只将屏幕边缘瓦片裁到实际消费的区域并保留原生像素格和过滤边。该参考使用基线的 WASM、原生准备程序和 GPU 栅格代码。参考与原始 worker 的差异仅为构建来源诊断和 source map 名称。完整视口从原数据计算，原始文档中的效果均开启。

在 3200% 下，默认窗口的 2,989,080 个像素和大窗口的 4,256,532 个像素，画布 RGBA 和窗口画布截图均为零差异。默认窗口 800% 的 2,989,080 个像素也与未经修改的基线一致。初始画面和缩回 100% 后的画布均通过同样的比较。

复跑入口包括桌面倍率回放、Rust 区域计算用例和真机浮点纹理对照。 [桌面倍率回放](../../frontend/design-desktop/scripts/check-high-zoom-sketch.mjs) · [Rust 区域测试](../../design-studio/crates/design-kernel/src/gpu/analytic_regions.rs) · [GPU 浮点对照](../../frontend/design-client/scripts/check-exact-prefix-textures.ts)

Apple Metal 上另外以原有逐采样着色器为参考，读取水平和垂直两次运算的 RGBA32F 比特。22 个用例合计比较 2,371,664 个浮点分量，差异为零。其中两个 479／480 半径的 alpha 用例和一个 147 半径的 RGBA 用例共比较 260,824 个分量。有效边界样本计入完整滤镜读取范围，邻域越过坐标上限则验证拒绝。

## Products 画板回放

同一份 FIG 导入后有 9,403 个节点。窗口采样使用 ScreenCaptureKit，DPR 2，普通移动每次发送 432 个输入，持续约 3.6 秒，使用三对交替的冻结基线和最终 release。缩放指 80% 附近的连续滚轮手势。旋转和调整尺寸使用 65% 的完整画板，各发 288 个输入，持续约 2.4 秒。调整尺寸同时记录右边缘像素、浏览器真正接收的位图和已呈现的位姿／纹理组合。

| 操作与观测口径 | 基线 | 最终构建 |

| 75% 完整画板首次拖动，可见更新/秒 | 58.7 | 57.6 |
| 80% 裁切画板拖动，可见更新/秒 | 35.9 | 34.8 |
| 裁切拖动 P95 可见更新间隔 | 66.1 ms | 68.2 ms |
| 从 80% 返回 75% 后再次拖动，可见更新/秒 | 4.7 | 45.4 |
| 返回 75% 后再次拖动的 P95 更新间隔 | 317.6 ms | 36.4 ms |
| 手形平移，可见更新/秒 | 57.1 | 56.8 |
| 滚轮缩放，可见更新/秒 | 57.9 | 58.2 |

| 整板旋转，已接收位图/秒 | 3.76 | 6.27 |

正式回放中，完整画板首次拖动的首个可见变化为 67.2 → 69.5 ms，松手就绪为 436.3 → 405.1 ms。裁切拖动的首个可见变化为 72.9 → 82.7 ms，松手就绪为 205.3 → 189.0 ms。以上是各操作的三轮中位数。机器上存在其他持续占用 CPU 的进程，绝对数值有波动。

25 个按住位姿的窗口画布、松手及撤销重做的画布内容、两份 1× PNG 和 Escape 取消后的延迟截图均与基线逐字节一致。三对调整尺寸与旋转均核对了最终几何、撤销、重做和对应画布。旋转与调整尺寸的显示更新率仍远低于 60 次/秒。

## 交替倍率后再次拖动完整画板

同一文档内连续执行 75%、80%、75% 的拖动并逐次撤销，可以重现完整画板在第二次 75% 拖动时切入逐位姿原生重绘。GPU 跟踪中，51 个参与合成的区域具有同一内容所有者，却带有两种像素契约。一种省略棋盘格字段，另一种显式记录关闭，背景覆盖检查因此拒绝补洞。

再次从 80% 返回 75% 时，松手就绪中位数从 305.3 ms 降至 62.9 ms。首次可见变化仍要等待原生视口，基线三轮为 318、492、244 ms，最终为 294、394、355 ms。后续持续拖动和松手的获益与这段启动等待分别计量。

直接合并两个契约的试验约可保持 58 次可见更新/秒，但四个位姿中的一个相对独立原生画布有 247,283 个像素不同，最大通道差 112。最终实现保留原覆盖检查，并仅在完整 sRGB 画板的背景覆盖被拒绝、原始文档与已就绪视口仍匹配时，将当次移动交给固定视口的精确原生纹理。后续同相位位移使用已验证的纹理，碰撞、相机变化和过期位姿继续受原有判定约束。 [画板覆盖处理](../../frontend/design-client/src/kernel/page-translation.ts) · [桌面视口交接](../../frontend/design-client/src/kernel/ResidentCompositeSurface.tsx)

在同一份原始文档上重新建立四份独立的目标位姿，以旧原生栅格器生成静态参考。最终构建按住时的四张完整画布均与参考逐字节相同。额外的四对 WindowServer 截图也与基线重复回放一致。对真实调整尺寸和旋转后得到的文档，用两版生产 WASM 在 1.3、1.5、1.6 倍设备密度编译了 54 个瓦片场景包，全部字节相同。
