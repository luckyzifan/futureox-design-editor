#### 2.3 内存压力测试

##### 测试1: 超大图像
1. 准备5000x5000像素PNG（25M像素）
2. 导入到画布
3. 放大到100%
4. 观察行为

**预期**:
- Level 0 admission失败（>16M像素）
- 自动回退到level 1（2500x2500，6.25M像素）
- 无崩溃，图像正常显示
- Console显示admission警告（可选）

##### 测试2: 多图像场景
1. 导入20张2048x2048图像
2. 放大到200%
3. 平移浏览所有图像

**Web预期**:
- 256MB GPU预算
- 可能触发LRU驱逐
- 旧图像重新加载时短暂闪烁

**Electron预期**:
- 1GB GPU预算
- 很少触发驱逐
- 流畅浏览所有图像

##### 测试3: 交互模式内存
1. 进入交互/原型模式
2. 触发多个转场动画
3. 观察内存使用

**预期**:
- 交互预算: 256MB（高于普通32MB）
- 支持多个全屏帧缓冲
- 动画流畅无卡顿

## 常见问题排查

### Q1: 3200%仍然失真
**排查**:
1. 检查`imageLevel`函数是否返回0
2. 检查`imageForAdmitted`是否正常工作
3. 查看Console是否有admission错误
4. 验证图像尺寸是否>4096x4096

### Q2: 平移卡顿
**排查**:
1. 检查zoom是否>=300%（应启用裁剪）
2. 查看DevTools Performance是否有长任务
3. 验证`getViewportRect`是否返回有效rect
4. 检查`isNodeVisible`是否正确跳过节点

### Q3: 内存超限崩溃
**排查**:
1. 确认是Web还是Electron
2. 检查`SURFACE_BUDGET_BYTES`值
3. 查看是否有内存泄漏
4. 减少同时加载的图像数量

### Q4: Electron无法启动
**排查**:
```bash
cd /Users/Apple/project/design-kernel/frontend/design-desktop
npm run build
npm run start
```
查看Console错误信息
