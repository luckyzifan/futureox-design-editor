# 渲染路径、缩放与拖动第二轮检查

本记录针对 2026-10-19 本地源码。用户报告：复杂文档超过 3000 个节点，初始化卡顿、缩放/拖动帧率不稳、3200% 卡死、Electron 报 GPU 表面内存预算超限。本轮按要求不执行 GPU 验收。静态缺陷、CPU 回归与用户现场现象之间不能直接画等号；未取得现场性能轨迹，不能宣布所有卡顿根因已确认或零失真已验收。

## 当前计算分工

- Electron 的 `KernelClient` 在存在 preload preparation bridge 时创建本地准备通道，经 Electron IPC、Node worker 到 `design-prepare` Rust 子进程。文档/布局/几何与场景编译、原生 CPU 帧准备在这里运行，消耗用户本机资源。
- 普通画布最终绘制仍由 `render-worker.ts` 中的 JavaScript GPU 调度器使用 Chromium WebGPU/WebGL2 完成。Rust 原生 GPU 诊断入口没有接管普通画布。
- 编辑器主线程的 `picking.ts` 与 `graph.ts` 仍使用 Rust WASM；部分布局、拾取、图历史和同步文档校验仍在渲染进程。不能称全部内核计算都已迁到原生进程。
- Web 的准备通道在满足能力/策略时使用独立 WASM worker；其余路径保留本地 WASM。图像解码仍使用 WASM 资产引擎。
- Rust 本地化不自动等于更快。原生 IPC 返回有帧拼接、缓冲区复制；当前原生 GPU 诊断还存在整帧读回/base64，直接接到画布未必加速。

## 已存在的优化，不应误判为缺失

Rust 平移交互支持最多 16 个节点的保留布局/路径快路。布局未脏时直接返回，不是每次拖动都完整重排全页。场景增量传输也已存在，但实际 pose 修改后仍需要编译、节点序列化与几何数据比对；传输是增量，不代表全部计算也是增量。

可见区域的瓦片计划使用 world viewport = CSS viewport / zoom，采样密度包含 zoom×DPR。因此 32 倍缩放本身并不必然让可见瓦片数量增长 1024 倍。需要单独检查模糊/阴影扩边、单个复杂路径、屏外依赖、准备队列与多帧驻留。

## 表面预算的意义

`gpu/renderer.ts` 的表面工作集是应用策略，不是显卡实际可用显存探测。默认 256 MiB，部分显示条件使用更高的动态预算。RGBA32F 表面占用为宽×高×16 字节，4096×4096 即 256 MiB；多个滤镜中间表面、留存源和显示纹理可能同时存在。

高倍缩放会放大效果的设备像素支持范围。小输出瓦片并不意味着其所有滤镜输入都很小。简单提高预算不能修复过期任务、错误复用或大效果支持域，也不能保证跨设备安全。

## 验证解释

CPU/WASM 编译、单元测试、模拟调度/驱动契约测试可以验证状态、坐标、所有权、取消和数据契约；不能证明实际 GPU 像素或 FPS。合成 3000 节点结果只适用于合成负载，不能代替用户原始复杂文件。最终执行结果见本轮验证记录。

## 连续缩放的新增产品边界

用户明确允许连续缩放期间临时降采样，结束后必须按最终倍率恢复精度。该许可不能外推到导出、静止画布或所有对象拖动。现有仅低倍率允许降采样和两帧稳定判断，不能充分表达一次持续滚轮/捏合手势；仅丢弃排队结果也不能打断已经运行的同步内核调用。调度改动须同时验证预览工作数量、最终精绘唯一性和过期结果不发布。

放大后的平移及曲线问题应分别检查：几何误差、设备像素相位、抗锯齿遮罩二次插值、缓存与新帧交接。整数设备像素平移可安全复用的条件不等于任意分数像素平移都能复用。

## 字体与 SIMD 的当前边界

字体资源读取与 WASM 编译可以并行，但后续字形加载/同步布局仍有 CPU 成本。字体缺失不能通过静默替换来宣称排版保真。Rust 字形及完整文本路径缓存有独立驻留上限，这不等于进程总内存上限或瞬时分配上限。

`build-web.py --simd` 目前是隔离输出的构建选项；允许 simd128 并不证明每个热点算法已向量化，也不证明对复杂文档有收益。本轮不把 opt-in 构建开关描述成已完成所有浏览器 SIMD 集成。默认兼容路径、特性探测、不同构建的数值一致性与真实负载收益必须分别验证。


## 本轮落实的共享管线修改

- 连续缩放状态与精绘分离：短间隔采最新目标；安静窗口加稳定帧后直接精绘最终倍率。静止输入不反复发布相同预览。
- 过期排队闭包及时清理；预算拆分子区域之间及异步编译/绘制后检查取消，不发布过期结果。正在运行的同步 Rust 计算仍不可抢占。
- 稳定后的分数像素平移采用相位匹配的原生瓦片；整数像素位置保留世界缓存。运动期间的重投影是过渡，不能标记为精确采样。
- 对象、保留图层和整页移动的复用入口补充像素相位检查；不能安全复用时进入已有 GPU 重绘路径，保留上一完整姿态等待新结果。
- 旧预览清理不再覆盖新可见状态；位图快照按统一设备像素比例保存，颜色管理文档不进入不支持其语义的 SVG/sRGB 快路。
- 保留拖动不再逐事件复制整份节点表；根节点边界归集改为单次遍历，并复用不变的文档/选择计划。
- 图片持久缓存按剩余字节淘汰；解码缓存独立限额并绑定文档/颜色身份；缓存限额不代表进程或显存总限额。
- 数值尺寸和字节乘积在分配前检查；可恢复预览预算失败安全回收临时资源并保留设备/显示纹理，设备丢失仍走错误恢复。
- 冷启动字体读取与 WASM 编译并行。首屏优先完整视口预览，再以完整精绘替换；无有效像素或失败时使用界面加载/错误状态，保持工作区底色，不修改文档透明内容或导出。

## 仍不能宣称完成的事项

用户原始复杂文件的 GPU 卡死与帧率问题尚无现场轨迹；合成负载未复现同样卡死。CPU 曲线用例通过不意味着所有弧线、字体或效果与 Figma 零像素差。单次同步几何编译不可中途抢占、跨全部路径的共享工作预算、主线程剩余同步布局/校验、全部 SIMD 热点及原生 GPU 呈现整合仍需后续工程验证。没有为这些未验证事项伪造性能结论。

## 本地准备传输

Electron FPR1 响应装配去掉整帧 Buffer.concat 后再次拷贝 payload 的路径。二进制直接从 stdout 分片复制到精确大小的自有 ArrayBuffer，再转移所有权；不转移 Node 池化缓冲区，不宣称跨进程端到端零拷贝。保持帧长度、序列、编码、队列和退出语义，并用真实 Rust/WASM CPU 帧作字节对照。

## 最终冻结验证结果

前端完整 Vitest：244 个文件，1593 通过、1 跳过、0 失败；类型检查通过。额外独立 Node 94 项通过；另跑的 renderer 25 项与 Vitest 重叠，不重复相加。659 个前端输入在运行前后保持一致。

桌面 Node 与真实 Rust/WASM CPU 准备桥组合 118 项通过；Rust 针对性 CPU 76 项、构建脚本 6 项通过。实际 CPU 帧桥接比较包括 256 KiB Float32 数据。详见 `testing/verification-phase2/results.json`；各组不是整机性能验收。

首屏/缩放过渡保持完整旧帧或完整视口预览，再替换精绘；无可用帧时工作区底色和加载/错误提示是 UI，不伪造文档已渲染内容。文档及导出的透明度不变。

默认 Vitest 与列出的 Node 合约通过不覆盖所有历史脚本：export-ownership.test.mjs 的旧源码提取器失败仍保留，详见验证记录。
