# 连续缩放交接

对应未关闭的 #58、#59、#60。#122 的安静粘贴板条门已经在当前 main 上：手势停下且精确瓦片都已缓存才选这条。本记录只说明这次相对 `origin/main` `fb2a2b98` 的交接改动，不证明显示器上的连续过程。

## 画面

- 连续放大时，已在缓存里、并且至少比它盖住的画面细两倍的瓦片，和原来的覆盖一起提交。并集盖不住就不发布。这只读缓存，不新开光栅。
- 局部材料帧不再先裁掉已经能盖住视口的连续画面。
- 从 3200% 缩回时，比当前相机粗过两倍的已缓存瓦片可以补裁切没有盖住的世界。没有这张缓存时，上一张图继续留着，不挖孔。
- 超过预览比例的完整帧，只有盖住当前视口才可以替换上一张。跳变仍马上请求精确帧；`zooming` 保持到和普通步进相同的 80ms 安静窗，结束时再唤醒一次。

## 不改的调度

完整拓扑逆向滚轮在 main `13b2356a` 上，输入结束后的 `ready + sharp` 等待是 16.184ms（步骤 wall 559.745ms）。当时的 #99 `b5e147df` 是 979.006ms / 1562.313ms，最终 RGBA 相同。那一版在运动格子已经缓存后，仍把整页粗覆盖交给唯一光栅通道。

这次不恢复那条路径。连续缩出不因为精确瓦片已缓存就排粘贴板条或页级总览。`coarsePanCoverNeeded` 在 `moving && continuousZoom` 时仍返回 false，包括 `quietStripAllowed: true`。安静粘贴板条、精确瓦片先于总览、平移跟手要条，都保持当前 main。预算、密度和像素公式没有改。

## 已运行与未测

在 `frontend/design-client`，用一份不加载 WASM 的 vitest 配置跑了覆盖栈、相机交接、平移条、导航底图和缩放调度策略。42 项通过。`navigation-backing.test.ts` 里「大页区域任务」会调用 `raster_tile_addresses_json`；这个检出没有生成的内核，也没有安装 `wasm32-unknown-unknown`，该项没有对着真实内核执行。上述通过项不包含它。

这个检出没有 Electron / GPU。拓扑 `.sketch` 若仍是 Git LFS 指针，就不能记录相对当前 main 的 `ready + sharp`。因此不能把单测写成那对等待已经不比 main 慢，也不能关闭 #58、#59、#60、#120 或 #122。冷缓存下没有粗瓦片时，缩出边缘仍可能露出原有页面底色，直到安静后的既有预取。33/100ms 和完整 G2/G5 不是本轮目标。
