# 第二批性能增量：保留效果，减少重复工作

本轮开始于已交付 `a9fb36a1ae40b3b30aa68a0aa5a7f2d3440c600697ab1ddae43ef0380c12c051` 快照。累计源码仍以 `71d32153e6f55b3723c99708b4c4c49ac7342e67` 为基准，保留前一批 API/MCP、本地记录、快捷键与导入导出修改。

## 交付范围

### 交互范围准备

将每个顶层节点重新筛选全部场景，改为一次遍历建立所属范围。继续使用相同的效果/描边扩展表达式和范围合并函数，保持条目顺序及浮点运算语义。

- 3,000 个根节点：属性读取 18,000,000 → 9,000。
- 独立于计数器的普通数据对照：该阶段中位耗时 201.67 → 9.16 ms；另一次为 219.67 → 11.15 ms。
- 3,016 节点 CPU/WASM 场景包含嵌套、遮罩、裁剪、阴影、背景模糊及隐藏内容；312×284 视口的 354,432 个 RGBA 字节一致。
- 60/90/120/144 Hz 的受控连续输入测试检查提交数、旧选择结果释放和最新输入发布。它们不是硬件帧率测试。

### 编辑器与多选操作

使用每次渲染/每次操作独立的父节点索引，避免在同一次计算中反复扫描文档。没有跨修改周期复用可变草稿索引。

- 3,000 个已选节点的属性面板挂载：父关系扫描 36,002 → 3。
- 受控 ABBA 两轮：旧面板约 24,717 / 25,977 ms，新面板约 97 / 99 ms。此测量从已经完成选择之后开始，不包含编辑器创建、文档打开，也不代表浏览器 FPS。
- 300 / 3,000 个节点缩放操作的父关系扫描分别由 303 / 3,003 降至 3 / 3。
- Alt 复制切换、智能对齐候选筛选和移动结束后的归属判断复用已有索引或集合，同时验证坐标、取消、撤销和重做。
- 深复制中的逐节点计算、布局排序仍有剩余开销，不能据此声称全部操作已为常数时间。

### Rust 局部变更缓存

用脏节点集合定向删除准备记录；程序缓存使用有序索引维护精确 FIFO、大小及数量，避免局部变更时扫描整份缓存。保留共享读者的写时复制保护。补充重复键替换、淘汰、重插入、字节计数和序列回绕验证。

局部失效阶段的测量下降，但重新编译、冷启动和相机变化并非普遍变快。部分编译阶段样本反而上升。计时属于共享主机上的观察性证据，受其他进程影响的运行已单独标注，不能用于整体帧率承诺。详见本轮 Rust 缓存报告中的逐阶段数据与取舍。

### 原生传输

保留原有生产分配器。试验方案只显示很小的中位数收益，未建立更稳定尾延迟或实际交互收益，因此没有纳入生产代码。

新增实现无关的字节完整性、真实 worker 转移/分离、分片、长度边界、异常与重复所有权测试。独立候选和报告标为 NOT SHIPPED，仅用于复核已放弃的实验。

## 验证依据

当前冻结后整体验证以 `testing/verification-performance-final/README.md` 为准。各专项报告位于 `testing/verification-performance-viewport/`、`testing/verification-performance-editor/` 和 `testing/verification-next-native-transport/`。前一批 `testing/verification-latest-final/` 是历史记录，不能代替本轮验证。

负对照必须真实失败：旧扫描路径会违反工作量断言；破坏边界扩展或输出末字节会破坏结果断言。测试没有通过删除实际内容、降低精度或把未执行项当作通过来改善数字。计数、断言数、测试数与覆盖率分别解释。

## 保持与限制

- 不修改渲染采样精度、字体/曲线/颜色/滤镜语义，也不缩短默认缩放静止窗口来制造更多任务。
- CPU/WASM/Rust 的结果一致性不是全部 GPU、驱动或所有用户文件的零失真保证。
- 真实 Electron/Web GPU 帧率、操作系统窗口/安装包和受阻 socket 仍未验收。
- 复杂复制/自动布局、大文档序列化及 Electron IPC 克隆等剩余开销仍需后续有证据地优化。

先用包内只读检查器核对精确前像。允许已知基准、上次已交付状态和本次后像的安全混合；遇到未知本地修改需停止人工合并。重建 WASM 与 Rust 桌面程序后再运行应用。累计包没有附带旧 ZIP、依赖或编译产物。
