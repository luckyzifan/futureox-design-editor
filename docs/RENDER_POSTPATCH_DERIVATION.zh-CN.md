# 已确认属性补丁后的文档派生

本阶段扩展此前仅完整加载确认的派生入口，不是任意差量协议，也不改变 GPU 所有权、效果数学或导出精度。

## 支持的范围

客户端从精确不可变 BEFORE/AFTER 对象计算完整文档补丁，只允许既有节点的有限属性变化，例如位置变换、尺寸、不透明度和可见性。补丁最多 256 个节点，保守 UTF-8 上界 64 KiB。新增/删除节点、拓扑、组件/引用、字体/图像资源、动画、根字段及不支持的属性变化不获得新的派生绑定，仍保留原编辑/完整加载回退。

前置状态必须已经绑定真实准备后端的收据。后端通过独立 guardedPatchReceiptV1 能力确认支持，并在任何状态撤销或修改之前验证 expectedBaseReceipt。陈旧或格式不符的前置条件明确拒绝，保留当前文档和收据；真正开始后失败的修改不恢复旧权威性。只有成功、非延迟的补丁 ACK 才绑定精确 AFTER 对象和新收据。后续已提交修改、重置、乱序 ACK 或源变化都不能复活旧绑定。

已确认的受支持补丁后，空差量派生无需再次构造或传送整篇文档。undo/redo 即便回到旧作者对象，也必须获得这次真实同步的新收据，不能仅凭旧 revision、ID、hash 或对象历史直接派生。未知作者字段不从原生规范化回读重建；原始作者对象仍是导出和后续编辑的来源。

## 失败与回退

能力不支持、前置条件缺失、超出子集或边界均不宣称已获得补丁后权威性。确定性的后端错误通过正常错误答复返回，不把它当作传输中断；未知的修改 IPC 结果仍退休会话，绝不盲目重放。取消呈现不取消已接受的有序文档同步。

## 验证与限制

实际 WASM 线程和新原生 sidecar 的真实 renderer adapter → host → Node worker → Rust 路径都验证了编辑、撤销、重做后派生，与独立完整加载目标的编译包、CPU 像素和 PNG 一致。原生测试还区分确定性陈旧/格式拒绝与“原生已执行后 IPC 抛错”的不确定情况，后者退休会话且不重放。

这些是有限夹具的正确性证据，不是用户大文件的整体性能测量，也不证明真实 Electron GPU/显示像素或所有编辑路径。更细 GPU 调度、资源压力下的等待与新日志的非取消错误仍需独立分析和验证；不能将补丁后少传文档宣称为全部卡顿的修复。

额外一次实际大文件原生后端正确性检查：21,797,593 字节导入文档中的可见根节点平移 32 px，受保护补丁 854 字节，随后空差量请求 291 字节、整篇文档载荷为零。派生结果的 159,360 字节包与独立完整加载修改后文档逐字节相同，且与修改前不同。包 SHA-256 为 01cf700f23ac0a601f692795ef493f4615f1300d04c420d86904299331cce5f3。该检查直接覆盖原生准备协议，不替代前端准入链、GPU 像素或端到端耗时验证；不随包分发原始文档或私有测试脚本。
