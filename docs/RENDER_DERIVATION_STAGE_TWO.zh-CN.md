# 版本化文档派生与完整瓦片检查点：第二阶段

本阶段不是“所有结构性问题已修复”。只开放完整加载已确认的同一不可变作者快照的空差量派生，并限制既有完整瓦片检查点连续让出的高优先级任务数量。它不改变效果数学、导出策略、GPU 栅栏或文档更新顺序。

## 版本化派生的实际准入

准备线程通过只读能力协商公开 preparation_capabilities_v1，并在成功加载/修改后返回顶层 stateReceipt 元数据。旧方法的 value 返回形状不变。旧原生后端不认识能力查询时正常回退，不因这个只读查询主动销毁会话；修改请求的传输不确定性仍按失败关闭处理，不盲目重放。

收据绑定真实准备会话、所有者、文档实例、通道、同步序号、资源序号与当前 token。derive_document_v1 仅接受 delta=[]、当前 canvas 收据和 interaction 目标比较交换条件。目标先在私有候选中完成静态 fork；版本、资源、动画、格式或计数器耗尽检查失败时保留原目标及其收据。新旧 operationId 的保守高水位规则拒绝重复和陈旧请求，不是自动重试账本。

前端只把一次成功完整加载的确认绑定到该请求闭包捕获的不可变作者对象。客户端 revision、文档 ID 或内容 hash 不能替代它；不从内核规范化文档重建作者数据。任意 canvas 补丁提交、重置或会话更换使该绑定失效。因此：

- 已确认完整加载之后，同一对象进入 interaction 时可以不创建、不发送整篇 JSON，只传小型空差量派生请求。
- 本阶段不把补丁确认重新绑定到新对象；编辑提交后的重复整篇传输仍可能存在。
- 未确认、不同对象、资源变化、不支持能力、陈旧目标、动画或其他拒绝都回到原完整加载路径，加载的是原请求捕获的目标，不是静默换成最新画布。
- 预览取消不取消已接受的有序同步。捕获输入独立于呈现 promise，最多 128 个待确认引用；超限在派发前拒绝，确认/错误/重置时释放。回退等待也有独立有界清理。
- 这是空差量路线，不包含瞬时变换差量、补丁后续证或持久化数据结构优化。VITE_DESIGN_DOCUMENT_DERIVATION=0 可关闭新派生准入。

## 完整瓦片检查点的公平性

只在原有“瓦片完成且成功交付”检查点，最多运行四个完整的更高优先级任务，然后让原批次重新检查取消状态并恢复通道/配置。提交屏障仍采用原来的完整排空行为。

这个限制以完成任务数计，不以毫秒计；单个任务仍可能很慢。没有在编码器中间切换、没有提前释放物理编译栅栏、没有新增 GPU 提交边界。队列整体公平性、更细的 GPU 所有权与安全资源退休仍是后续工作。测试中的队列所有权模型不等于真实设备性能验证。

## 新日志不能支持的结论

一份复现日志的最终请求 954，在截断前物理编译 1756 至少还有 6.010 秒未观察到完成；最后输入后低密度覆盖观测延续 6.573 秒。这些都是右删失观察，不是测得的最终完成时间，也不能据此判定程序永久冻结或确定根因。该工作负载仅有 canvas 请求，新空差量交互派生不能被宣称修复它。

另一份独立会话中，缩放从 32 反向到约 0.29365，最终请求 1202 用时约 537 ms，finalComplete 距最后输入约 575 ms。最后一次质量采样在约 436 ms 时仍为 81.25% 锐利覆盖、最大放大 6.03，但之后还有三个瓦片到达、绘制数从 366 降至 16，因此不能声称低质量持续到最终完成之后。必须在终态补充质量观测，不能把旧采样当成完成时的质量。

上述日志根因和终态质量观测另有诊断工作；诊断仪表不等于行为修复。真实 Electron/GPU/显示扫描、输入到光子、参考工具速度或整体稳定性仍未由此验证。

## 本阶段的可复现验证范围

实际导入文档为 21,797,593 字节。在一次真实 WASM 准备线程测试中，已确认完整加载后的派生请求为 315 字节，整篇文档载荷为零；派生后 589,740 字节 GPU 包与独立完整加载同一文档的包逐字节一致。该测试验证协议与包一致性，不是 GPU 像素或输入到显示的延迟测量。

新增诊断只传受限数字与分类，不传作者内容、资源数据或收据。准备请求通过通道生命周期标识与请求号关联，分别观察 WASM 执行边界或原生桥接/管道边界；取消不释放仍运行的物理栅栏。等待采样有界，不增加超时取消。操作生命周期记录意图、类别、数量、版本与软件快照确认，不证明屏幕像素正确。

DETAIL 模式在完成标记实际提交后强制一次有界 96 点覆盖采样，避免终态落入常规采样节流窗口。它沿用软件覆盖模型，没有 GPU 回读，不代表物理显示像素或显示扫描完成。上述诊断用于区分问题发生的位置，未宣称解决尚未确定根因的长编译。


## 严格整数设备像素平移的采样相位保留

新增保守准入只针对已有原生采样计划：同一文档对象、修订、页面、会话、后端、显示能力和色彩管理状态，非相机相关场景，密度不变，两个轴都满足严格整数设备像素位移且小数相位精确相同。没有容差或吸附，不放宽抖动、滤镜、导出或效果计算。符合条件时移动阶段保留原生相位，避免先切到零相位、停止后又切回原生相位导致可避免的重绘。

现有复现日志可确认整数位移，但缺少相机相关性、色彩/显示状态等完整准入证据，所以不能保证用户那次反向缩放后的场景一定受益。这是带保护条件的重复工作优化，不是对全部重绘或长编译的修复承诺。

既有 viewport-state 事件现在附带严格受限的相位保留、相机相关性与采样模式数字，配合修订与 DPR 观察准入，不增加新事件或定时器，不输出配置名称、作者或资源内容。
