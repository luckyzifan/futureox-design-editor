# Futureox 品牌与 Futureox Design 图标设计说明

版本：2026-10-20 · 已选方向：Mac clean v5 / no canvas controls / Indigo + White。

2026-11-02 起，运行时主标改为靛蓝圆角方形上的字母 F（`#3459D4` 与白色）。下文仍记录此前的 F/D 轮廓说明，不再描述当前窗口图标、网页图标或工具栏标记。

本说明将已选择的图形与配色整理为可执行的品牌规则。下述寓意是本次设计提出的解释，不是虚构的品牌创立故事、商标权声明或对未来产品的承诺。

## 1. 品牌、产品与工程标识

- **母品牌：Futureox**。跨产品保留一致的命名、蓝白识别、几何纪律与简洁交互。
- **当前产品：Futureox Design**。面向设计编辑，其产品特征可以加入画布、路径、节点等设计工具语言。
- **工程名称：futureox-desgin**。仓库、既有可执行文件、文件路径与标识保持原拼写；品牌显示名的整理不代表批量重命名工程。

选定视觉参考：[Mac 图标与小尺寸预览](branding/futureox-macos-selected-preview.png)。该图对应用户在天蓝色比较后选择回到的靛蓝版，随后按已批准的优化，保留白色圆角方形底、缩小 F/D 主体、统一 45° 斜切，并按最新要求移除全部外部画布角标。天蓝色只是被否决的比较方案，不属于当前品牌色。

## 2. 一眼看到什么，第二眼发现什么

### 第一层：F 是主识别

F 对应 Futureox 的首字母。它是完整的独立轮廓，不依赖字体安装，也不是把普通字体加粗后直接当作标志。竖向主干建立稳定重心，上臂与中臂明确形成 F。

两臂右端之间保留开口，避免闭合为 P。这个开口既是字母辨认的关键，也是图形中的呼吸空间。小尺寸首先应看见 F，而不是先去辨认细小角标。

### 第二层：D 表达 Design

外轮廓左侧有切角，右侧是连续的 D 形曲面；独立主标内侧 F 的弧线呼应外轮廓；Mac 精修版则把 F 两臂末端统一为与外侧切角一致的 45° 斜切。D 对应当前产品 Design，并不是把品牌 Futureox 改成 FD，也不意味着所有未来产品必须沿用 D。

直线与曲线的组合，可解释为“精确结构与自由塑形并存”：左侧像可定位的边界，右侧像可编辑的曲线。这个解释来自图形自身，而不是借用其他产品的视觉故事。

### 第三层：设计感来自构造，不再叠加工具控件

最终 Mac 图标不再包含外部角标、控制点或选框。设计工具的特征由 F 的精确斜切、D 的连续曲面与充足留白共同表达。界面中的路径节点仍可服务真实编辑任务，但不作为品牌图标的装饰。

这避免把应用图标看成“正在被选中的对象”，也让小尺寸识别更干净。旧角标方案只作为修改历史保留。

## 3. 几何构造与可编辑性

### 标准主标

- 采用 512 × 512 的设计坐标。
- D 形主体由原生矢量网络构成，关键点与贝塞尔控制柄可编辑。
- F 的左边界为 x=136，竖干右边界为 x=200，主要竖干宽度为 64。
- 顶部从 y=128 起，中臂从 y=256 起，主干止于 y=384。
- 上臂右侧终点 y=208，与中臂顶部 y=256 之间保留 48 单位开口。
- 使用真实闭合路径与曲线，不把细节烘焙进不可编辑的位图。

坐标用于描述当前母版，不应代替直接使用 SVG/FD 文件。重新绘制、独立描摹或凭截图拉伸都容易造成曲率和间距漂移。

### Mac 应用图标

Mac 图标使用独立的系统图标承载层，不改变主标本身：

- 512 坐标下，白色圆角方形底位于 (16,16)，尺寸 480 × 480，圆角半径 104。
- 内部 F/D 按 0.66 等比缩放，平移至 (87.04,87.04)，保留边缘安全空间。
- 不包含外部角标或节点控件。原左上角线及节点由真实 MCP 删除命令移除。
- Mac 版 F 上臂末端从 (368,128) 切至 (304,192)，中臂末端从 (312,256) 切至 (256,312)，两者均为 45°，与 D 左侧切角一致。
- 本次从已选精修 v4 原生 FD 出发，经 MCP 仅删除两个角标控件节点；节点数从 7 减至 5。剩余节点的几何与样式逐项验证不变，并验证撤销/重做；旧版 FD 保留为历史。
- 1024px 图像由原生渲染器按 2x 输出；ICNS 由对应原生像素生成。

这是当前 Electron 应用采用的传统 ICNS 资源设计。它没有声称通过真实 Mac Dock、系统遮罩、Icon Composer 多层材质或所有 macOS 外观模式认证。预览是图标作品，不是系统截图。

## 4. 配色：蓝白优先

| 用途 | 颜色 | 规则 |
| --- | --- | --- |
| 主品牌蓝 | `#3459D4` | F/D 主体、交互状态及必要强调 |
| 品牌白 | `#FFFFFF` | F、Mac 承载底、反白内容 |
| 文档深色文字建议 | `#172B3A` | 说明性正文，非新增标志色 |

以靛蓝替代此前较亮的蓝，是当前已选方向。不要在不同平台随意回退到此前 `#2563EB`、荧光黄或被否决的天蓝。

白色与主蓝按标准 sRGB 相对亮度公式计算的对比约为 **5.96:1**。这是两个实色的数学对比，不等同于整个应用通过无障碍审计；细线、抗锯齿、透明度、缩放和实际界面背景仍需检查。

品牌标志不能代替状态反馈。成功、错误、选中等状态还需文字、形状或可读标签，不应只靠蓝色深浅区分。

## 5. 尺寸、留白与错误用法

### 使用尺寸

- 16px：浏览器 favicon、极小系统图标。优先保住 F 的轮廓与开口。
- 24–32px：工具栏、应用标题区、紧凑列表。
- 64–256px：启动入口、产品列表、安装展示。
- 1024px：系统图标母版与高分辨率输出。

当前已检查 16、32、64、128、256、1024px。原生导出还保留 512、1024、1536px 的 1x/2x/3x PNG。图标比例必须保持 1:1，不用 CSS 拉扁、裁掉右侧弧线或挤压安全边距。

### 留白规则

独立主标与外部文字、边框、其他品牌之间，建议至少保留一个主干宽度的空隙，即母版坐标中的 64 单位。极紧凑工具栏可用较小的视觉间距，但不能把控件边框贴在字形上。

Mac 白色底内的安全边距已包含在专用母版中，不能把独立 D 轮廓直接铺满圆角底，也不能把整个 Mac 图标再次套进另一层白色圆角框。

### 禁止事项

- 不使用其他品牌的标志、配色组合、彩色胶囊堆叠或可辨认剪影。
- 不镜像、旋转或水平拉伸 F/D。
- 不把主标做成渐变玻璃球、金属浮雕、厚重投影或发光描边。
- 不自行补回 F 的开口，使其近似 P。
- 不在16px图标上增加工具按钮、文字或更细的控制点。
- 不把“当前方案的原创构造”表述为已完成商标检索或法律排他性保证。

## 6. 平面 UI 与图标家族

这组图形适合平面、清楚、可操作的界面。建议用留白、层次、轻边框与有限色块建立结构，而不是依赖大量渐变或悬浮卡片。

- 工具图标统一使用可编辑 SVG，遵循一致的网格、光学尺寸与描边体系。
- 普通工具图标采用简洁线性表达；选中状态可以配实色底或清楚轮廓，不需要每个图标复制 F/D。
- 路径节点、角标等语言应来自真实编辑概念。装饰不能伪装成可点击控制点。
- 画布区域优先呈现用户作品。品牌蓝应集中在选择、主操作与品牌入口，不把整个工作区染蓝。
- 白色卡片、工具条和面板之间要有可感知的边界；深色主题不是把所有颜色简单反相。

## 7. 轻动效：默认开启，但尊重减少动态效果

以下是品牌交互规范建议，不声称这些行为已全部实现：

- 默认允许轻量淡入、焦点过渡和短距离位置变化，让状态变化可追踪。
- 建议悬停/按下反馈约 100–160ms，面板开合约 160–220ms；按任务调整，不机械套用。
- 使用温和缓出，少用弹跳、回弹、持续呼吸、旋转或循环闪烁。
- 优先改变透明度与合成层位移；不要为了装饰触发画布内容反复重绘。
- 系统或应用启用减少动态效果时，关闭非必要运动，保留立即可理解的状态反馈。
- 保存、撤销、错误、权限状态不能依赖动画结束才可见；动画也不能阻塞下一次操作。
- 品牌图标默认静态。启动时不要求播放复杂商标动画。

## 8. 未来产品如何复用

Futureox 是母品牌，Futureox Design 是一个产品。因此未来产品优先继承 F 的识别逻辑、主蓝/白、间距与平面风格；产品专属含义可以变化，不必强行都解释成 Design。

建议采用“稳定母品牌 + 明确产品后缀 + 少量语义变化”：保留核心几何语言，使用一处可辨认的产品结构差异。不要仅靠换颜色区分产品，也不要给每个产品创造完全无关的视觉系统。

新产品图形仍需经过16/32px辨认、深浅背景、命名与可访问标签检查。当前文件只定义复用方法，不代表任何新产品已被授权命名、立项或发布。

## 9. 实际制作链路与交付边界

当前图形通过本项目自己的 **JSON-RPC MCP → DesignMcpServer → OperationBackend → Editor/WASM** 创建。传输采用内存 NDJSON；操作与原生内核不是模拟返回值。

- SVG 和 FD 经 MCP 资源导出；FD 已验证解码一致、重新打开、编辑与撤销。
- PNG 由产品原生 CPU `VectorEngine.render_region_png` 输出；不是浏览器截图，也不是外部图像生成。
- ICO/ICNS 用 Pillow 对原生像素编码；Windows/Linux 使用独立主标，Mac 使用带白色圆角底且无外部控件的专用资源。
- 源码保留作者脚本、可编辑母版和资源引用测试。
- 没有声称完成真实各操作系统 GUI 检查、安装器生成、签名、公证或商标清查。
