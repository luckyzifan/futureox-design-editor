[源码] 编辑反馈与精细渲染分开。预览使用已有 Rust 路径／字形和浏览器矢量显示；只有受支持的效果／填充范围启用。可独立合成的最上层子树分为固定背景和活动层，纯移动只更新活动层的 CSS 变换；蒙版、祖先裁剪、背景采样、混合依赖及结构变化不能进入独立层路径。画布命中、选框与布局手柄跟随实际预览文档。指针事件按帧合并、松手使用最终坐标；面板最多按 80ms 周期刷新，结束时立即更新；精细请求在编辑停止后合并执行。预览明确显示“编辑预览 · 正在细化”，不满足 exact readiness、不用于导出；精细 GPU/CPU 合同和原资源上限保持。

[边界] 此即时矢量显示是交互预览，并非逐像素 GPU 参考输出。超过 5000 节点、渐变模糊、玻璃／噪声／纹理、角向／菱形填充等不使用该预览路径。复杂效果的精细计算仍可能耗时；本轮未证明所有场景稳定 60 FPS，也没有把不同相机／缓存状态的 9.72s 与 1.40s 当作 A/B 加速倍数。

## 2026-10-15：117 实际编辑差距复核

本轮按用户反馈核对拖动、编辑、左右面板和延迟渲染；未修改运行时代码。当前源码与下文 10 月 10 日历史记录有差异：Option 拖动复制、跨画板重挂、智能选择、圆弧参数等已有实现，不能继续将旧“未实现”清单当作现状，也不能将其存在等同于完整 Figma 行为通过。源码身份与验证边界见[本轮证据](../../testing/review/design-117-interaction-audit-2026-10-15.json)。

### 已确认的问题

- [已验证，真实 WASM／Editor，非鼠标 E2E] 从下载目录原始 117 导入，得到 752 节点：106 text、587 vector、41 group、9 frame、9 rectangle。对「组合 51」调用属性栏同一 `resizeNodeDimension` 和编辑提交路径，将宽度 `238.0000610351562` 改为两倍，提交后的宽度和实际世界边界仍为 `238.0000610351562` 左右，七个子层几何未变。组尺寸由子内容重新归算，单独写组的 width 不能完成组 resize。画布组拖柄使用 transform，和属性栏走了不同语义。
- [源码] `Canvas.tsx` 普通 resize 对单选 text/group 仍保留矩阵伸缩，对其他单选图层才转换成局部宽高和路径顶点修改；文字拖框因此没有实现 Figma 的“改文字框并重排”合同。`selection-properties.ts` 的属性栏宽高又走另一条路径。应统一 resize 命令，并明确区分文字框尺寸、普通 resize 与 K Scale。
- [实测页面诊断，非 FPS] 独立浏览器 117 页面保存的最近一次完成请求为 `refineMs=9719.50`、`compileMs=801.20`、`graphMs=8740.10`、`checkpointMs=3666.70`、`finishMs=139.40`，后端 WebGPU，DPR 2，failedTiles=0。缓存命中不重置这些字段，故这些值不一定属于当前 28.3% 相机，也不等于某次鼠标动作的输入延迟；graph 包含 CPU 编码／等待，checkpoint 是其中子阶段，不可相加或称为纯 GPU 耗时。
- [源码] 选择框读取 live 文档，拾取读取已呈现快照；文档编辑把新文档送进完整瓦片流程。`CanvasLayoutHandles` 和 `CanvasSmartSelection` 只在 `presented.document === renderedDocument` 时可见。完整像素更新慢会让内容、选框与高级手柄不同步，是“拖动延迟／功能忽隐”的明确排查方向，不能靠已有 camera 缓存推断对象拖动已经跟手。
- [源码／当前 UI] 单选 Inspector 顶部只有位置、旋转等输入，常用对齐／翻转没有像真实 Figma 那样直接呈现；多选面板能批量修改基本数值、简单纯色、添加描边／效果，但没有完整编辑已有多选描边与效果栈的交互。功能入口完整性和执行正确性须分别验收。

### 后续修复顺序与验收条件

1. [设计，P0] 统一 resize/edit 命令与属性语义：先修组 W/H 无效、文字框 resize 和画布／面板结果不一致；覆盖变换父级、锁定、约束、撤销。
2. [设计，P0] 把交互呈现单独测量：记录 pointer→选框、pointer→对象预览、release→精细帧三段；拖动时使用正确的活动对象预览及稳定背景合成，依赖模糊／蒙版时显式失效；保留最终精细输出合同。优化前先采 trace，不能只降画质、加缓存或把 graphMs 当 GPU 时间。
3. [设计，P1] 补齐左右面板工作流：层级上下文、多选属性栈、常用对齐／翻转、布局与约束的上下文入口；已有能力不重复造入口。
4. [设计] 固定 117 的「组合 51」及其背景、数字、标题作为连续验收样本：整组移动→进入子层→文字框调整→组 W/H→K Scale→复制→重挂→撤销／重做→保存重开。每步同时核对图层结构、属性值、选框和实际像素；单元测试或“WebGPU 清晰”状态不能替代这条工作流。

重新读取用户提供的节点 `278:3`（128×128 玻璃样例）并用 Figma 的 PNG 导出交叉检查，又对历史节点 `101:3` 做相同导出。三个当前参考的 RGBA 一致；当前内核 CPU/WebGPU 与历史 PNG 一致，但与当前 Figma 有 **1,420 / 16,384 像素不同，最大通道差 2**。当前严格 Figma 像素门禁未通过。未覆盖旧参考、未降低预览精度、未将参考图嵌入渲染结果，也未将差异归因于一个尚未证实的原因。来源、参数与哈希见[参考记录](../../testing/review/design-desktop-macos-gui-2026-10-10/interaction-followup/figma-reference/README.md)。该节点是玻璃内容样例，不能作为编辑器工具栏的设计稿。

| 操作 | Forma 实现与通过条件 |
| --- | --- |
| 椭圆绘制 | O 后四方向拖动；创建草案用同一精确内核呈现，落笔复用同一几何与 ID |
| Shift 与 Option | Shift 约束等比例；Option 从中心创建；两键组合保持中心与比例；松按修饰键重新计算 |
| 点击创建 | 默认100×100；画板400×300；线段100长水平线；以3 CSS px的实际手势距离区别点击与拖动 |
| 多边形与星形 | 新多边形默认三角形；绘制中上下键调整点数；选中后画布手柄与属性输入可调点数，星形有内半径手柄；一次撤销恢复 |
| 直线 | 窄竖线不会变为默认大矩形；Shift 以45°方向约束；预览与成品使用同一端点；Option 对称创建 |
| 铅笔和画笔 | 铅笔为独立等宽工具（Shift P或Mac Option P）；B为压感画笔，各自保持宽度、颜色和平滑设置；Shift绘制直线段，Cmd取样纯色描边 |
| 椭圆进入节点编辑 | Enter或双击只创建编辑叠层，原文档保留内核 Arc；无移动点击、退出编辑不产生转换或撤销项；再次Enter退出 |
| 实际修改椭圆锚点 | 首次真正改点/控制柄才创建Bezier网络；一次Undo恢复原Arc。四段cubic是编辑后的几何，不宣称与原生Arc数学等价 |
| 保存与取消 | 草案不混入持久文档；Esc/取消指针丢弃草案；完成手势只有一项历史。钢笔未完成路径注册为待提交输入并绑定文档/页面 |

| 锁定与事务 | 锁定自身或祖先的节点不能从画布柄绕过保护；活动手势中不能插入Delete、方向键、工具切换或外侧属性修改 |

## 右键菜单

菜单根据空选、单选、多选、文字和锁定状态生成。项目中没有实现的操作不显示空入口。

- 撤销、重做、复制、剪切、粘贴到此处、粘贴到原位、创建副本、删除。
- 编组、解除编组、水平/垂直翻转、向上/向下、置顶/置底。
- 锁定、解锁自身或父级、隐藏/显示、缩放选区或全部内容。
- 选择重叠图层（包含锁定层，过滤隐藏层）、编辑文字、现有矢量转换与描边轮廓化。
- 上下/Home/End/Enter导航、Esc关闭、视口边缘约束，菜单不会把指针事件送回画布。

“粘贴到此处”将复制内容的世界坐标包围盒左上角放在右击位置，保持多选相对关系、静态仿射父级下的动画与一次撤销。普通内部Duplicate原位复制；顶层画板向右排列的24单位间距为Forma当前约定，未经实时Figma对照，不称为相同间距。跨文档原型闭包等不能完整保留的情况仍明确拒绝，不能以悄悄删除语义制造成功。

入口：[菜单](../../frontend/design-client/src/CanvasContextMenu.tsx)、[状态矩阵](../../frontend/design-client/src/canvas-menu-model.ts)、[统一命令](../../frontend/design-client/src/editor-commands.ts)。

## 仍未对应的能力

椭圆的起始角/扫角/圆环内径工具尚无模型与完整内核链路；多边形/星形圆角不能只显示控制柄就算支持。Figma Draw 的自定义Stretch/Scatter brush、纹理笔刷和高级工具未完整实现。右键的Paste to replace、多目标粘贴、完整Flatten、Copy as code/PNG/SVG、插件和组件高级操作仍须各自实现、定义格式合同并验收。

本阶段未重新证明复杂HDR达到流畅目标；精度合同继续不降采样，不把基础形状通过外推为复杂材质性能通过。独立 macOS Electron 包已通过真实鼠标/键盘创建、多选点击/拖动、撤销、菜单按键隔离和 Rust/SQLite 重读，详见后续验收记录；真实触控笔、原生中文输入法、Finder/Dock、OS剪贴板等仍需单独补齐。
