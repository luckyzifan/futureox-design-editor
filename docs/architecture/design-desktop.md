## 2026-10-19 本地准备与通信计算

[源码] Electron 的 `coreDesktop.preparation` 默认把文档/补丁 JSON 编码、请求排队、NDJSON framing 和二进制回复处理放到宿主 Node worker；它拥有独立 `design-prepare` Rust 子进程。文档安装、布局、几何准备、GPU 命令编译、CPU 渲染和 PNG 导出由本地 Engine 完成。Web 保留 WASM preparation worker。输入、编辑 UI、GPU 呈现和既有图像资产接口仍属于各自前端职责；这不等于桌面完全移除 WASM 或全部改用原生 Metal 呈现。

[源码] 前端仅把不可变文档或局部补丁交给宿主编码。保存、恢复及打开的 JSON 编解码也由独立本地 document codec worker 承担；编码结果按捕获时的文档代次缓存/合并，同步 dirty 判断保持 O(1)，异步完成不能覆盖新编辑或把旧保存回执当作新版本。编码/提交按文档 revision 排序，提交后不等待渲染结束再接受下一次输入。GPU 命令及像素使用 `FPR1` 二进制回复，不经 Base64 或 JSON 数值数组搬运。会话绑定发起窗口，最多 4 个；每会话最多 32 个待回复请求，NDJSON 在途加排队上限 96 MiB，单帧输入 68 MiB、二进制输出 128 MiB（保留 8,388,608 像素 × RGBA f32 的既有合法上限）。错误明确返回，纯计算请求超时回收该会话，不盲目重试写入。关闭、导航与退出回收其专属 worker/子进程。

## 范围与状态

[设计] 用户选择 Electron，明确沿用已有 React UI，以自研设计内核构建结合 Figma 设计能力与 Sketch 本地工作方式的跨平台桌面产品。目标平台为 Windows、macOS、Linux；共享代码不代表三端已经构建或验收。本阶段为单窗口离线文档流程，不声明完整 Figma/Sketch 功能等价。

[源码] 编辑器继续位于 `frontend/design-client`，画布复用 Rust/WASM 与 WebGPU/WebGL2 路径。`frontend/design-desktop` 是 Node.js/Electron 系统宿主（当前宿主源码为 JavaScript，React 编辑器仍为 TypeScript），不复制另一套编辑器。Rust crate `design-studio/crates/design-desktop-backend` 提供文件、恢复、SQLite 文档主存、系统字体和独立目录索引，直接复用 `design-kernel` 文档验证；普通离线编辑不依赖 PostgreSQL、Redis 或云端账户。

## 边界与通信

[设计] React 仅使用 preload 暴露的窄能力接口。Electron 主进程拥有原生文件对话框和所选路径；渲染器只持有文档句柄，不能指定任意文件系统路径。主进程与 Rust 子进程通过有界 NDJSON 标准输入/输出通信，不开放 HTTP/TCP 本地服务。日志不得混入协议 stdout。

[设计] 页面采用本地资源协议、内容安全策略、隔离上下文、禁用 Node 集成和开启 sandbox。IPC 验证发送者及顶层页面，不将完整 Electron API 暴露给页面。外部导航、弹窗和未授权权限请求默认拒绝；文件中的内容不能获得宿主能力。

## 文件、恢复与并发

[设计] `.forma` 继续使用 JSON 文档。文档限制 32 MiB，IPC 帧限制 64 MiB；模型验证支持现行 schema 1–6。打开、另存为、取消及失败不应丢失当前画布；桌面工作模式不静默调用云端同步。

[设计] Rust 通过同目录临时文件与替换完成保存，先校验既有文件 SHA-256 基线；显式空基线表示只允许创建，不允许覆盖。发生可观察的外部修改时拒绝保存并保留用户当前编辑。该机制不构成对所有外部、不协作写入程序的原子 compare-and-swap。

[设计] 保存的确认绑定提交时的文档快照；请求期间产生的新编辑不得被标为已保存。替换已提交后目录同步失败必须区分“文件已更新但持久性保证不足”，不能错误地宣称原文件未改变。关闭窗口须等待保存结果和最新 dirty 状态，取消关闭应继续保留编辑。

[设计] 恢复快照位于应用私有目录，恢复按用户选择加载为未保存副本，不能自动覆盖原始文件。容量不足、损坏快照、后端退出及保存失败应可见，不能通过静默丢弃旧快照制造成功。

## 2026-10-09 源码与验证边界（历史批次）

[源码，2026-10-09 恢复后] 后端使用 Tokio 异步 stdio 控制循环、单个解析任务、单个执行中的阻塞任务和有界 FIFO。排队/运行请求合计最多 8 个、请求 wire bytes 合计最多 64 MiB；读入暂存和响应另有帧界限，这不是总 RSS 上限。`health`/`cancel` 可越过文件队列；已开始的原子保存不被取消伪装成回滚，EOF 排空已接纳任务。调度器 2 线程、Tokio blocking 上限 3，SQLite 单连接；未声称实时延迟或吞吐提升。详细错误、取消和资源合同见[后端 README](../../design-studio/crates/design-desktop-backend/README.md)。

[源码] SQLite 只保存本机项目、已登记目录及文件索引元数据，不替代 `.forma` 文件和恢复快照，也不引入 Core 租户/RBAC。`userData/catalog-v1.sqlite3` 由主进程选择，schema 1 版本化迁移、单连接、32 MiB 页面上限及完整性检查在后端执行。每根目录只扫描直接子项，最多检查 2,048 条、保留 512 个文件；达到界限显式返回部分结果。损坏/未来版本/不可用目录库保留原数据并使目录能力降级失败，独立文件对话框和恢复能力仍可用；不自动重建数据库。

[源码] 目录元数据不是持久授权。每次进程重启须通过原生对话框重新选择目录；主进程仅把会话句柄和显示信息交给 React。宿主持有最多 16 个目录授权，数据库最多登记 32 个根目录。打开文件前须在本会话扫描，文件 ID 由主进程绑定到扫描出的直接子项；后端重新核对根目录/祖先身份。该检查是可观察变化检测，不承诺抵抗具有同用户权限的恶意进程在检查间隙替换又恢复目录。

[源码] `--core-cpu-only` 必须在 Electron 启动时显式传入；普通产品启动没有自动开启此开关。主进程在 ready 前关闭硬件加速、GPU 和软件 GPU rasterizer，经 preload 固定传递 CPU-only 策略；worker 不允许请求或本地偏好放宽该策略。CPU-only 绘图不导入 GPU factory，色彩呈现禁用 GPU presenter；PNG 继续强制 CPU。此分支有源码与纯函数检查，不等于本轮已启动 Electron 或证明任意驱动环境行为。当前云环境禁止运行全部 GPU 相关测试，也不通过软件 GPU 或弱化 sandbox 绕过。

[本轮局部已验证] 中央验证记录核对了 Linux x86_64 后端 39 项（lib 9、desktop_files 18、catalog 7、runtime_lifecycle 5）、精确 Node 宿主 allowlist 46 项、真实本机 sidecar stdio 5 项、纯 CPU 策略 11 项及隔离 DesktopCatalog 组件 6 项。各组范围独立列示，失败尝试和重跑不累计为新用例；其中 GPU-preference 命名用例明确排除，未运行。后端产物 SHA-256 为 `fe0fcdec90b4d9de9b54df564ca09d5b1a71e3128f39b1a4dd32932df87dde04`。这些是 Linux 文件/控制面及指定前端单测的证据，不是全产品验收。

## 后续边界

- 原生 wgpu 当前的离屏能力不等于已接通原生桌面窗口画布，本阶段保持现有 WASM 画布。
- Sketch 文件导入、完整 FIG 保真、系统字体管理、云端协作、团队库及插件宿主不由 Electron 外壳自动提供。
- 新交付包必须累计包含此前所有修复，以初次克隆 `fa0ac97c5ac36373b233a82b475de37529a62be4` 为补丁基线，并验证所有变更文件，不要求依次应用旧 ZIP。

## 2026-10-10 首次画布拖动与缩放修复（历史批次）

[源码 + 本机验证] 双缓冲画布在后台完成 SDR/HDR 像素写入，以同一次 React 提交切换显示帧、视角和尺寸，避免可见 canvas resize 清空与旧视角错配。视口外最多 192 CSS px 的余量可覆盖小幅拖动；平移先重投影已完成帧。Electron 菜单与 Cmd/Ctrl +/−/0 映射到画布命令，页面缩放固定为 1，滚轮缩放保留指针下的世界坐标。

[源码 + 本机验证] GPU 预算改为读取当前帧的实际纹理占用，包含需要浮点效果的 SDR 文档。预览最多进行三次有界降密度尝试，仍无法容纳时按整数屏幕偏移分块，保留内核效果 halo，在私有数组中拼完整帧后再换帧。最低预算为 128k 像素。块读取保留浮点 HDR；该路径不改变导出。

[本机局部已验证] 真实 React/WASM/Metal 回归采样 438 帧，画布/叠层错位、可见帧缺失、可见 canvas resize 均为 0；SDR 分块与整帧逐字节一致，HDR 最大绝对差约 8.35e-7，保留大于 1 的线性值。真实 Electron 独立窗口的样例拖动和 100%→200% 缩放已执行。最新结果、截图与产物身份见[本轮画布记录](../../testing/review/design-desktop-macos-gui-2026-10-10/canvas-motion/README.md)。

[该批次限制] 当时分块为显存不足时的完整帧回退，并非跨视角复用的持久瓦片缓存。短拖动覆盖检查不能证明任意速度、任意距离都无边缘补绘延迟。复杂 HDR 200% 样例完整重绘约 1.17 秒且降低预览清晰度，尚未达到 Figma 的流畅度或 Retina 清晰度；原生触控板硬件手势、多屏和全部效果的块边缘仍需独立验收。
