## Core intents

The thin automation registry registers layout.add and layout.remove, which share commands/layout-command.ts with Editor.autoLayout and LayoutPanel. Each uses the existing isolated staging, permissions, session/document/revision fencing, native Editor commit and history/receipt machinery. The optional internal freshness fact cannot be supplied by request JSON.

layout.add requires ids (1–1000 unique IDs) and mode (horizontal or vertical). Optional gap is 0–100000; padding is a complete typed object {top,right,bottom,left}, each 0–100000. Optional order is scene or axis. Optional id/name apply only to a newly created wrapper; supplying either for an existing frame/group rejects. New wrappers default to name 自动布局, gap 12, padding 16 on all sides, hug/hug, transparent/unclipped/pass-through. Existing containers merge omitted layout fields with existing authored values and Core defaults.

One ordinary frame or group is updated in place, with group converted to frame. Other same-parent ordinary selections get a new frame at the first selected sibling slot. Selected ancestors cover descendants, but invalid explicit targets still reject. Final flow repositions nodes by design: arbitrary scattered selections are accepted, not rejected for failing a geometry-preserving inference. Noncontiguous wrapping does not promise unchanged overlap with intervening objects. Wrapper defaults to axis order; existing container defaults to scene order. Axis uses parent-local origin, with scene sibling order as stable tie-break, regardless of input IDs. Hidden/absolute children retain their slots. The result reports target ids, actual childOrder, created, and reflow (false for an unchanged plan).

layout.remove requires explicit ids of ordinary frames. It is not recursive, ungroup or restore-before-add. It deletes active layout, freezes container sizing to fixed/fixed, converts direct-child fill axes and parent-assigned stretch/hug cross axes to fixed (grid: both assigned axes), retains current authored geometry and child order, and resets direct-child constraint references to the current parent dimensions. Native constrain computes deltas from those reference dimensions; reset prevents old resize deltas becoming active again after leaving flow. Already inactive frames are unchanged without forcing sizing writes. Existing layout.set {layout:null} still only removes that facet, intentionally not this new semantic intent.

## Admission and limitations

Authored layer locks and authorization are distinct. Adding/changing layout on one existing ordinary frame, including no-argument UI inference, and removing layout from explicit ordinary frames are in-place property intents: the target, descendants and ancestors may remain authored locked. Identity and topology are retained. Group/type conversion and multi-selection wrapping are structural intents and still reject any locked target, ancestor or affected descendant atomically. The distinction is derived internally from the actual operation and target kinds; request JSON cannot supply a lock policy or trusted capability. Existing structural callers of the shared selection index retain strict locking by default. Real write grants, session/document/revision fences, instance restrictions and derived-batch guards are unchanged. This corrects the earlier overbroad structural classification and preserves the original locked-child shortcut fixture without weakening its assertions. Existing LayoutPanel spacing/sizing/constraint/grid property editors retain their property-edit behavior. Components, instances and instance-internal nodes reject; no detach is performed. Boolean/mask container add rejects. Bound/variable/style-dependent geometry, board/connector/text-path dependencies, invalid matrices and over-10000-node affected subtrees reject explicitly. Changes inside active layout ancestors reject; removing under hug ancestors and current min/max conflicts also reject. Nested layout inside the selected frame remains intact. These are bounded phase-A limitations, not fake success or full Figma support.

Every add/remove after an earlier batch leaf rejects unsupported_derived_batch_geometry, even a seemingly harmless predecessor. Commit and reread before retrying. An initial layout command followed by supported non-geometric edits can stage and commit once. Preflight has not been expanded to promise derived geometry validation. No per-leaf whole-document native layout is introduced. Wrap reuses the admitted selection index with prepareSelectionWrap, so one layout plan builds one parent map and reuses shared matrix/reparent/list mechanics.

## UI strategy boundary

Explicit horizontal/vertical and remove use the shared command. Existing no-argument UI add preserves its original world-bounds wrapper geometry and 16-unit outset, plus native inferred_layout_json and applyInferredFrame after shared admission. Pending edits settle first; the document/session owner is recaptured and checked again inside the change callback. That inference, including banner absolute flags and inferred flow slots, is deliberately not claimed as MCP layout.add parity. Grid UI retains its existing native grid field strategy after the same strict admission; grid is not a new layout.add mode.
