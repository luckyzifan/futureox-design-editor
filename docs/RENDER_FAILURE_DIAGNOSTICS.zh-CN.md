# 渲染失败与资源准入诊断

此改动是诊断，不是对等待、内存回收、失败重试或渲染结果的修复。它不改变 GPU 栅栏、资源销毁顺序、预算阈值、效果数学或后端选择。

## 失败分类

终态 error 事件补充受限数字 failureCategory、failureStage、failureCode、errorClassCode、rendererCode，以及编译/水合/渲染图/回退/失败尝试计数。backendCode 仍只表示实际观察到的准备后端，不能用安装了哪个二进制来推断。

类别：0 未知，1 取消，2 不支持，3 资源预算，4 设备丢失，5 验证，6 协议。阶段：0 未知，1 请求，2 加载，3 派生，4 补丁，5 编译，6 图像水合，7 编码/driver finish，8 提交，9 栅栏等待，10 呈现，11 回退，12 渲染图，13 资源准入。0 代表无法确定，不是成功。

只对源码中列出的完整固定错误 token、实际错误类型和明确源阶段分类；不按包含“内存”“设备”等词猜测未知错误。不会把消息、堆栈、cause、文档、节点 ID 或资源名送入这些字段。内部标记保留原异常对象；既有预算包装保留分类，不改变异常控制流。

尝试计数最多 65535，并带截断标志。它们记录被观察到的操作尝试，不是唯一物理故障数量，嵌套操作可能描述同一次传播。被回退恢复的失败每个请求最多增加一条 failure-summary，不逐瓦片或逐阶段刷屏；终态错误和摘要使用已有有界日志缓冲并及时刷新。

## 既有 admission 栅栏

已有 fence 记录可以携带 admissionKind（0 主动清理，1 已知分配前置检查）、admissionPressure，以及请求字节、工作集、预算、候选可回收量、池字节/数量、上传候选数和图像缓存条目数。它们都是等待前的快照，不是已释放字节，也不是物理图像/图集总显存。字节受限于 16 GiB、数量受限于一百万，非法值忽略。

关闭诊断时不创建这份元数据或为其扫描池。开启后也不增加事件、定时器、GPU 命令、栅栏等待或回收操作。原有完成后才销毁资源的边界不变。

## 怎样解读

先区分失败发生阶段和是否被回退恢复，再结合同一请求的准备边界、队列、编译、水合与栅栏记录。等待时间和不同阶段可能重叠，不能简单相加当作墙钟耗时。高次数 admission fence 需要区分硬分配压力与主动清理，再判断候选池大小；这版不会为了减少数字而跳过等待或提高预算。

测试覆盖分类隐私、未知错误、包装传播、计数边界、已有队列调用次数和资源完成/销毁顺序。模拟 GPU 契约不等于实际设备性能、真实 GPU 像素或用户复现根因。新日志仍需要同版本、可比场景的复现，不能把诊断字段的新增说成卡顿已经解决。
