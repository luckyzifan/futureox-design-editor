# 高倍缩放后不再把低分辨率预览留在画面上（2026-11-08）

这轮修的是 macOS Electron（Retina）上看到的两张画面，不是 `render_rgba` 的毫秒数。内核和 WASM 没有改。上一轮离屏裁剪画板的对照仍然有效：WASM `e544c39626befb1d875f0219f7d7f574c665947175c01598790bb7d84c7edec1`，zoom 3.2 是 626.522 ms。没有 Electron、GPU、上屏计时，也没有 Figma 或 Sketch 的帧时间。不是 33 ms 或 100 ms，也不是完整 G2/G5。

`origin/main` 仍是 `b6d906a41db7273a8889140122edddaf26324af5`。没有合并 pull request。没有使用 GitHub Actions。`frontend/design-client` 的 `tsc --noEmit` 通过。

## 看到的问题

文件「01有料素材」，Compose Mail / New Message。检查器上的 x=388、y=162 是父画板里的局部坐标。父画板在世界坐标 4697,860。组的世界盒子是 x=5085、y=1022、w=664、h=707。

1. 从 2400%–25600% 跳到 Shift+2（约 119.7%）或「实际大小」（100%）时，整张 New Message 卡片先变成放大的低分辨率图，文字和 REPLY 看不清。大约 1.5 秒后才变清晰。来源是整页图集或上一帧位图，按新相机做了超过 2 倍的放大。
2. 在 2400% 使用「居中显示所选图层」时，画面停在空白画板的网格上。组的世界中心不在那个相机里。

## 留下的

显示用的旧位图，采样倍率和目标相机相差超过 2 倍时不再画出来。这包括 CSS 重投影、不超过 1024px 的整页图集、覆盖底层，以及参考表面。超过这个限度的缩放会在下一轮请求精确帧，不再把旧图留 80 ms。缩小到一半以内的滚轮仍然可以沿用上一张图。

居中所选使用世界盒子。场景条目的盒子如果包不住节点的世界中心，就改用世界矩阵。已呈现的帧如果根本不会出现在当前视口里，叠层（像素网格、选区）跟着当前相机走，不再把旧画板的网格留在屏幕上。

内核的 `render_rgba` 没有改。2400% 下居中之后，卡片中心的像素是卡片自己的填充，不是画板网格。
