## 根因和修改

| 路径 | 实际问题 | 本轮修改 | 仍需注意 |
| --- | --- | --- | --- |
| Sketch 复合轮廓 | 所有子路径 booleanOperation=-1 被当作独立 Union，反向内轮廓的孔洞被填满，遮盖蓝色、渐变与透明层 | Rust 增加 schema 16 的 compoundNonzero/compoundEvenodd，保留方向与 winding rule；导出保留源语义 | CPU/GPU 相等不能替代与源文件独立预览的比较 |
| 线性渐变 | 密集 RGBA32F 参数场反复生成/上传，大条目进不了 32 MiB 缓存 | 仅固定系数证明某坐标轴无影响时，保留 1 行/列；参数仍 f32、四采样不变；相同字段在生成前查缓存 | 斜向/其他渐变仍走原路径；64 MiB 字段 guard 和缓存预算不变 |
| 手势编译 | 传输为 delta，但完整场景节点、顶点、曲线仍重编译和序列化 | 原生相同相机下重编译受影响的完整根子树；静态节点/程序地址保留。达到原 32 MiB 保留上限则完整压实。全局策略或 extent 变化走完整路径 | 准备/全局依赖检查和 JS 容器复制仍有全场景工作，不能称整体 O(变化节点) |
| GPU 精确资源 | 每个姿态对全节点做 JSON 签名和路径比较 | 解码器私有回执同时证明节点与原程序前缀未变，复用静态资源，只检查改变的节点 | 普通缓冲区覆盖/压实没有此证明，仍完整比较 |
| resize | 主线程每次预览重复识别依赖、求布局、查询所有几何 | 一次手势保留独立根索引；尺寸通过原 Rust 布局/约束求解器；仅合并变化节点，保留其他画板身份 | 组件、跨节点引用等没有独立性证明时保留完整路径 |
| Canvas 几何/索引 | 每个新文档都重建当前页几何和所有网格单元 | 完整差分识别变化根，保留未变 SceneEntry；空间索引对变化项更新单元并保留查询顺序 | 仍需容器复制与排名遍历；没有隐瞒成全增量 |
| 组件属性编辑 | 无关节点经 Immer/JSON 重复遍历，清理不存在的丢失依赖 | 对完整 authored 差分证明拓扑未变，缩小 override 捕获，跳过无关依赖清理；补齐 vectorGeometry override 字段 | 结构/定义变化保留完整流程 |
| Rust 组件 patch | patch 后整文档 clone 两次、再次计算全差分 | 先用 patch 计划影响根；常驻文档只备份受影响子树以回滚，局部派生后编码局部结果；保留全验证/容量检查 | 验证、预算计数和组件依赖扫描仍不是全增量 |
| FIG 保存/恢复快照 | 全文档对象跨 renderer→host→Worker，再逐项检查/编码 | 常驻 codec 保留字段/节点编码片段；首次全量、之后只发变化值和键顺序；最终 JSON 仍逐字节等于 JSON.stringify | 完整 JSON 的组装/落盘仍存在；base 丢失必须显式重新安装 |
| 缩放输入阻挡保存 | 大型源工作区的 PendingEditContext 使缩放被当作文档属性；相机改变而 doc 不变，被误判提交失败，留下隐藏 draft | ViewControls 显式隔离文档输入 context；视图输入不占用文档草稿/历史 | 已复现失败、Esc 解除后成功保存；新构建再做 GUI 回归 |
