# 高倍率手势缩放大面积空白复现记录（2026-10-22）

用户报告：3200% 下手势缩放出现大面积空白。本记录为同日真机复现与根因定位，**修复未在本轮落地**。

## 复现（真实 Electron + Playwright 输入，HEAD 36afde0 前的默认构建，flag 关）

⌘+ 阶梯缩放至 3200% → 14 次滚轮（55ms 间隔）继续缩放至 ~6400% → 定时截图（[s1–s6](.)，日志 [host-stdout.log](host-stdout.log)）：

| 截图 | 时刻 | 画面 |
| --- | --- | --- |
| s2 | 手势进行中 | 正常（导航预览覆盖） |
| s4 | 手势结束 +1.2s | **中央偏右 + 底部约 40–50% 空白** |
| s6 | 缩回后 | 恢复 |

## 根因（日志证据）

高倍率窗口内 68 个请求：手势期间导航预览覆盖画面；手势一停，**第一条全密度精确请求 rid 71 耗时 5116ms**（1710×1776 @ zoom 64），后续瓦片组各 ~420–470ms 逐个补齐。空白 = **预览帧退役早于精确瓦片覆盖完成**的间隙：预览在相机 settle 后立即隐藏，而高倍率下精确瓦片要数秒才到，期间无任何层覆盖。窗口内 0 次预算失败、coverage 诊断无缺口（覆盖率按相机几何统计，测不出"该区域当前没有可见像素"）。

与逆向结论一致：Figma 瓦片缓存用代标 LRU **保留旧瓦片直到新瓦片替换**（GLUE-JS-MINING §2.5，`makeLeastRecent` 降权而非隐藏），不存在" retire 后悬空"状态。

## 修复方向（下一场实施）

导航预览帧退役条件从"相机 settle"改为"精确 plan 覆盖完成（`complete`）或超时兜底"，即 Figma 式 never-blank 保留：`ProgressiveSurface` 中导航帧 `active` 生命周期与 exact `complete` 对齐；需保留现有内存/正确性门（预览是 1M px 上限的临时帧，不能无限驻留——对齐 Figma 的周期回收）。验收：本复现脚本 + s4 不再空白 + 空白帧计数为 0。

## 关联未竟项

三项结构优化（场景编译增量、中间表面瓦片作用域化、帧内可打断调度）未开工；其中编译增量是 [自适应密度验证](../verification-interaction-adaptive-density-20261022/README.md) 后的新主导项（compile 263–789ms）。
