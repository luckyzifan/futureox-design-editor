# 快速缩放时的页面内容交接

对照起点为 `db83526f`。两边都用项目的 Electron、真实 WebGPU 和同一份未改写的原件。普通画布用同修订号的页面预览补已知缺口，完整源使用绑定到源快照的临时导航图。清晰状态仍由当前视口的精确瓦片决定。[构建和逐例数据](measurements.json)

## 固定回放

桌面构建命令为 `bun run build --fast`。117 的画布是 855×886 CSS 像素，以图层 `98906AEB-08B4-49AA-9173-C99496434AAE` 为中心从 300% 开始。向右平移七次再原路返回，随后按住 Ctrl，以约 12 ms 间隔输入八次 90 单位的垂直滚轮，缩至 34.6%。最后一次输入后取过渡截图，再在同一相机取清晰截图。FIG 经过相同的缩放轨迹，完整拓扑源定位到「模板二」后按同一倍率比缩小。Retina 复测核对了实际 DPR 2 和 1710 像素的显示缓冲宽度。

暂白像素须满足过渡截图的 RGB 三通道均至少 248，同时停稳截图对应位置至少一个通道低于 200。合法白底不计入。下表中的边长是这些像素能组成的最大实心正方形。原始统计保留了细节在低分辨率预览与精确绘制之间的差别。

| 原件 | 修复前暂白像素 | 修复后暂白像素 | 最大方块边长（前 → 后） |
|---|---:|---:|---:|
| 117 Sketch | 181,554 | 210 | 131 → 2 |
| FIG | 62,980 | 249 | 94 → 2 |
| 拓扑完整源「模板二」 | 28,877 | 1,719 | 22 → 4 |

三份文件的过渡相机均与目标相机一致。平移、缩小、反向缩放的九张停稳截图逐像素复核，均与对应基线相同。拓扑这一冷视口在本机从过渡截图到清晰截图仍约需 35 秒。

## 连续反向缩放

普通 Electron 窗口在实际 DPR 2 下对 117 输入 64 次滚轮，每八次反向。用窗口的 `webContents.capturePage()` 采集 63 帧，另一次独立打开文件，为相同的九个相机各生成精确参考。逐帧用界面显示的倍率数字配对，63 帧均逐像素匹配到唯一倍率标签。在固定画布内部，每帧检查 504 个 32×32 CSS 像素的方块。精确参考中超过 95% 像素的 RGB 三通道都低于 100，且样本中超过 80% 像素的三通道都至少为 235，才算错误白块。63 帧均无此类白块。

离屏 CDP 录屏的起始帧曾漏掉已有的 GPU 内容。直接用采样时间去匹配普通窗口与最近的 rAF 相机也产生了三个误报，独立精确参考和同图倍率标签将合法画布背景及白色字形与缺块区分开来。本轮统计限于实际采集的合成帧，没有测量物理扫描输出延迟。

20 个客户端定向测试文件中 155 项通过、1 项跳过。桌面文件接口 11 项通过，Rust 源快照往返组 24 项通过、1 项既有忽略。完整 G2/G5、跨平台、全部效果和全场景的 100 ms 精修目标仍需分别验证。
