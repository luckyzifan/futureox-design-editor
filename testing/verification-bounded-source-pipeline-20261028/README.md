# 全源画布有限流水线：2026-10-28

已将全源画布从单瓦片请求改为最多两瓦片的小批次，接入原有 PrepareAhead：一个 CPU 准备任务可以与当前 GPU 绘制重叠。GPU 指当前渲染器的绘制/编码任务，不是显卡数量或 GPU 核心数；其他窗口的渲染器仍遵循原来的独立生命周期。

本轮没有修改 Rust、GPU shader、采样、数学精度、HDR、图片 mip 策略、导出、工作集预算或编辑/存储协议。正式运行时改动仅为 `NativeSourceSurface.tsx`；额外两份测试验证生命周期和工作区接入。未提高任务队列或 GPU 客户端上限。

## 实现与来源

- 一个 source render 批次最多两块，同一 surface 同时最多一个批次。Worker 原有 PrepareAhead 只保留一个下一块准备任务，GPU 队列继续只有一个 raster owner。
- 第一块收到后立即进入原呈现路径，不等第二块。全部所需瓦片及当前相机/DPR 得到有效呈现回执之后才标为清晰。
- 取消判断针对尚未完成的瓦片：已经完成的离屏块不会误取消仍有用的第二块。过期、重复、源切换后的结果不能污染新缓存，也不能释放已被接受的纹理。
- 批次缺少任何应返回瓦片时明确失败，不能把局部结果报成完成。

冻结基线为 HEAD `2954a77fe22a12f806d91351ec95e5186f9b562a` 加已有工作树修改；精确输入见 `baseline.json`。独立工作目录避免覆盖用户原件和其他工作。首次冻结遇到并行修改后重新同步；缺少未跟踪 JSON 夹具的初次 typecheck、错误 wasm-bindgen 路径的初次构建均保留日志，属于建立测试环境过程中的失败。

基线还存在 App 已传 nativeSource、Canvas 未接收的连接缺口。隔离候选先参考正在运行的 V43 构建恢复连接；随后主工作区的另一项工作已提供更新的连接实现，本轮保留该新版 Canvas 并重新组合验证，没有用旧恢复版本覆盖它。最终交付文件见 `integration.json`。

WASM 与 native 都从冻结源码重新构建；源码、产物、profile 见 `initial-build-manifest.json` 和 `build-manifest.json`。后者绑定复测的组合构建；前者不能冒充组合后的结果。

## 实机速度与像素

真实 Apple Metal-3、WebGPU、DPR 2，画布 800×600 CSS px。经实际桌面 largeDocument.open/canvasSnapshot 导入只读 Sketch 原件，完整源模型留在 native。基线和候选使用完全相同的 Rust/WASM/GPU 产品，只切换冻结旧 surface 与新 surface。

每个视口各一次不计入的预热，随后 A1/B1/B2/A2/A3/B3，三次/版本。以下计时是**源模型加载完成到当前视口完整呈现 ACK**，包含编译/绘制/交接；不是纯 GPU timestamp、物理 scanout 或 FPS。读取像素在计时结束后执行。原始冷载入和预热数值均保留在报告，没有隐藏到性能样本里。

| 已测构建与场景 | 单块中位数 | 两块中位数 | 相对变化 |
| --- | ---: | ---: | ---: |
| 首个冻结构建：拓扑 400% | 15135.4 ms | 13757.2 ms | 改善 9.11% |
| 首个冻结构建：117 首素材适配 | 1836.5 ms | 1805.1 ms | 改善 1.71%，收益小 |
| 组合复测：拓扑 400% | 11125.4 ms | 10271.1 ms | 改善 7.68% |
| 组合复测：117 首素材适配 | 1841.5 ms | 1770.8 ms | 改善 3.84%，低于 5% 显著保留目标 |

组合拓扑完整源为 124447 节点、306 素材，固定相机 `(-3112,-812,4)`；117 为 753 节点（含源 stage）、1 素材，相机见 `combined-117-summary.json`。它们是指定视口，不代表全览或所有内容。

组合拓扑首块可见中位数 9203.3 → 8781.3ms；每次均绘制 11806 draws，峰值纹理均 402577856 bytes。组合 117 首块 704.9 → 689.0ms，峰值纹理均 239786292 bytes。两块候选分别每次触发 6/8 次提前准备；单块为 0。所有运行同时最多一个 source raster 批次。

两份素材、两套构建的所有完成帧，各自同视口 RGBA8 内容像素 SHA-256 一致。`evidence-hashes.json` 绑定原始报告和 PNG；目标像素 readback 不等于物理显示器逐帧验证。纹理峰值不增加也不意味着总 CPU 内存完全相同：提前准备允许多驻留一个既有预算内的 packet。

目标拓扑场景超过运行前登记的 5% 改善门槛。117 收益小，不作普遍加速承诺。测试时本任务没有并行构建或重测试；初轮有进程采样，组合复测仅有边界采样，正常桌面后台活动仍存在。样本规模有限，不将约 8% 推广到所有文件或硬件。

## 取消与功能

- `controller-old-failure.log`：旧 surface 在同一“两块批次”断言上失败，新实现通过。
- `combined-final-regressions.log`：10 文件、71 测试通过，包括 source controller、准备通道、客户端、FIFO/优先队列、真实 Canvas/Editor/WASM 接入和滚动条。传输/设备 mock 的覆盖没有冒充硬件。
- `combined-typecheck.log`：组合类型检查通过。主工作区合入后的结果另见 `main-typecheck.log`、`main-regressions.log`。
- `cancellation/` 与 `combined-cancellation/`：真实 GPU 上放大、反向缩放并返回，均实际取消两次请求，最多一个批次在途，无渲染错误，返回后像素与原精确视口一致。返回就绪观察分别为 1764.7ms / 287.5ms；不同构建的一次观察不能用于取消性能倍数或中位数非退化结论。
- `ordinary-gui.json`：初个冻结候选的独立完整工作区，通过实际 UI 创建矩形、90→180 宽度修改、撤销回 90、重做至 180、保存到 SQLite、关闭并从本机库重开核对 180×70。`ordinary-storage-rows.json` 的版本 2/4 与 3/5 分别具有相同快照 hash，印证撤销/重做内容。
- UI 实际生成 1×/2×/3× PNG，尺寸为 180×70、360×140、540×210；1× 写入 `ordinary-1x.png`。它是基础导出 smoke，不是完整 HDR/复杂效果/600 图标导出矩阵。
- 初次通过 AX setValue 调整数值触发了输入校验，已按 Esc 取消，再通过真实键盘输入完成；保留这一自动化失配，不计作成功修改。
- 原始两个 Sketch 文件前后 hash 不变，用户既有 V31/V32/V43 窗口和文档未修改。

## 合入与剩余边界

三份本轮源码/测试已按前置 hash 合入主工作区。合入时另一项工作仍继续修改六份 GPU/诊断文件；具体清单在 `integration.json`。本轮自己的文件与已测版本一致，保留那些后续修改，**没有把冻结构建覆盖成默认 desktop/dist**。因此本文速度数字绑定上述已测组合，不能自动覆盖后续 GPU 修改。

本轮只关闭有限流水线的指定场景与生命周期检查。完整 G2/G5、3200%/全部快速运动、跨平台、物理输入到光子、device-loss 全矩阵、HDR/export 全矩阵以及全源直接编辑仍为 NOT_RUN/既有未完成状态。全源首块仍可能等待数秒；这不是整个渲染体验已经完成。

回滚仅在目标文件仍等于 `integration.json` 的 after hash 时，恢复对应 before 文件；新测试同样先核对 hash。不要回滚本轮未拥有的 Canvas/GPU 文件。验证入口保存在 `frontend/design-client/verification/bounded-pipeline`，`build-lab.mjs` 构建隔离入口；原始样本不附带在交付内容中。
