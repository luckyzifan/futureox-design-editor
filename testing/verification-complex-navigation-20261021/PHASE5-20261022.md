# Adaptive backdrop phase certificate — CPU and GPU evidence, 2026-10-22

This change adjusts only the native painter certificate's **sufficient
binary32 addressing proof**. It does not change document values, matrices,
material coordinates, coefficient generation, four sample phases or shader
arithmetic. It preserves the existing capture derivation and original
fractional phase; admitting a previously rejected crop can change its integer
capture origin and allocation size relative to the support-disabled legacy
scene. The existing strict painter launch/request gates remain default off.
Unsupported cases return the complete previous same-crop scene; they do not
receive partially accepted metadata.

## Exact-grid argument

The previous proof required every ordinary-backdrop capture origin to be on
the 1/512 grid and restricted the relevant global/local results to magnitude
less than 32768. A finer but exactly represented origin was rejected even
when all operations fit a smaller exact binary32 domain.

The new proof first requires each original binary64 origin to round-trip
bit-for-bit through binary32. It extracts the smallest dyadic fractional
denominator from the binary32 exponent and significand trailing zero bits.
It never multiplies the origin by a large scale to guess whether a rounded
result is integral, and never replaces the original origin with a rounded one.

Let `k = max(9, all capture-origin fractional denominator bit counts)`. The
grid is `2^-k` and the strict result bound is `L = 2^(24-k)`. A result on that
grid with magnitude below `L` is exactly representable in binary32. The
minimum `k=9` preserves the old widest domain; integer/coarser backdrops gain
no larger coordinate budget. Thus k10 uses 16384, k11 uses 8192 and k12 uses
4096. Excessively fine/subnormal phases fail the size/result bounds.

The original checks remain necessary and unchanged:

- Legacy/planned origins differ by an exact integer; allocation dimensions
  are integers no larger than 8192, with the existing coordinate limits.
- The joined source span plus both outward-rounded tent reaches and neighbour
  guard is strictly below `L`.
- Every global capture centre, integer tent tap, clamp endpoint and `base+1`
  reconstruction stays in the exact-grid domain.
- Every relevant subtraction from either integer source endpoint, including
  the half-pixel and neighbour guards, also stays strictly below `L`.
- Capture origins and their explicit size/half-pixel endpoints remain exact
  binary32 values.

Integer source origins themselves retain the old ±1M coordinate allowance:
they are exactly representable integer operands. The separately bounded
subtraction results must lie in the selected grid domain. It would be
incorrect to claim that all source operands multiplied by `2^k` fit 24 bits.

These conditions make the additions/subtractions exact. Integer translation
then preserves the bilinear fractional weights and global reconstruction,
including the real zero-weight neighbouring loads. This is only the address
part of the certificate: all existing dependency, retained-source closure,
geometry and area-budget proofs remain required.

cargo test -p futureox-design-kernel --test gpu_painter_support_regions unsafe_backdrop_phase_rejects

Run from `design-studio`. The first invocation passed **10/10** phase tests,
including the original coarse-domain/tap-boundary cases, the real 117 k10
origin, k10/k11/k12/k16 tightened positive/negative boundaries, distant local
subtraction rejection, negative origins/cross-zero translation, literal f32
address comparisons and unchanged fine rotated-phase rejection. The second

entire same-crop legacy scene, including when stage metadata is unavailable.

The initial unit-test compile failed on ambiguous float-array types in the
new test. Explicit `[f64; 4]` annotations corrected the fixture; the final
commands above passed. No release, full workspace, WASM or GPU acceptance was
performed by this focused run.
