# 独立 byte-alpha integer-tent 候选（默认关闭）

此模块只为可证明的 RGBA8unorm 阴影 alpha 消费提供精确整数帐篷核；不替换普通 RGBA/HDR 滤镜、Rust/CPU 导出或文字/路径覆盖。

现有 GPU `vector.wgsl::tentInteger` 使用 u32 累加，并按商余数执行 RNE。原半径 512 的准入限制不能直接抬高：r1920 的全 255 numerator 是 5,640,192,000，已超过 u32。CPU 在大于 512 的域使用其现有浮点 moment 路径；本候选没有改动该路径，不能将候选与以前不存在的大半径 GPU 输出宣称逐位一致。

新模块 `frontend/design-client/src/kernel/gpu/byte-tent-prefix.ts` 使用 GPU 前缀 sum/moment 和显式二字 u64，系数严格为中心 `6r−2`、内部 `6(r−|i|)`、外端点 `1`，分母 `6r²`。每轴写回真实 RGBA8unorm，再由下一轴读取 byte alpha；不能把两轴合并后只量化一次。RGB 为零，调用者必须证明后续只读取 alpha。

## API 与资源边界

`await ByteTentPrefix.create(device)` 后调用 `encode(encoder, sourceTexture, targetTexture, { radius, axis, source, output, scratchBudgetBytes? }, availableBytes?)`。只接受整数半径 1–2048、RGBA8unorm 的 `.a`、单层 2D 单采样、整数全局格点及其 tap 安全坐标。拒绝 R8/R32F lane、source/target 别名和不足预算。输出可在输入外，使用透明零边界。

每次 encode 返回独立 lease，真实 prefix 和逐 band 的独立 uniform 分配全部计入 `lease.bytes`。默认每轴至多 2 MiB，两轴同 encoder 合计至多 4 MiB；没有内部 submit、fence 或未记录的池。调用者必须将该字节数纳入 driver ledger，并一直持有到覆盖这批命令的真实队列完成边界。

提交对应 encoder 后调用 `lease.markSubmitted()`；submitted lease 禁止 `discardUnsubmitted()`。`lease.retireAfter(actualCoveredCompletionPromise)` 只在成功后销毁资源；失败或不确定完成不会销毁，且恢复 submitted 状态，不能误当作 unsubmitted 销毁。`discardUnsubmitted()` 只适用于已放弃、绝不再提交的 encoder。普通取消不能当作完成证书；device loss/destruction 另有显式 disposal。

模块本身不被渲染器自动调用。任何 driver 集成都必须保持单独的严格 opt-in；证明脚本要求 `VITE_DESIGN_BYTE_TENT_PREFIX=1`。此记录不授予默认启用或抬高旧 shader 限制的依据。

## 可复现验证

轻量 CPU 测试：在 `frontend/design-client` 运行 `bunx vitest run src/kernel/gpu/byte-tent-prefix.test.ts`。包含直接 BigInt tap、独立正部三次积分有理 oracle、prefix 代数、r1920/2048 的 u32 溢出及精确 half-tie、两轴中间量化、透明边界、坐标/lane/别名拒绝、显式资源完成与 band uniform 独占。

独立实 GPU 脚本为 `frontend/design-client/scripts/check-byte-tent-prefix.ts`。先可用 `bun scripts/check-byte-tent-prefix.ts --prepare-only` 准备两个独立 CPU oracle；实际设备运行需 `VITE_DESIGN_BYTE_TENT_PREFIX=1 bun scripts/check-byte-tent-prefix.ts`。每次必须使用新的空 evidence 目录。

- 半径 ≤512：直接提取当前生产 `at`、`blurAt`、`tentInteger` 函数，真实 GPU 与 BigInt/独立有理 oracle 三方对照。
- 半径 1920/2048：GPU 与两种独立精确 CPU oracle 对照，另含超过 u32 的长 moment、透明跨界、全 255、随机、half-tie 和真实两轴 byte 中间边界。
- 真实 abandoned encoder 和显式 covered completion 生命周期；不将队列提交 ACK 当作回收证书。

CPU focused **18/18**、**32 组**双独立精确 fixture 准备已通过，状态为 `prepared-no-gpu`。首轮实际设备编译在 `ByteTentPrefix.create` 因 WGSL 保留字 `pass` 失败，尚未执行像素；该失败记录保留。已改为 `settings`，按 [W3C WGSL 保留字表](https://www.w3.org/TR/WGSL/#reserved-words) 的 146 词静态扫描，三个模块没有剩余冲突。这仍不等于 shader 编译通过。

独立数值 proof 保留显式请求 16384 texture limit 的长 moment 案例，并另加 8192 长度真实 carry 控制。每次先记录 adapter 实际上限、请求值和 device 上限，不能把独立 proof 的能力条件当作生产 driver 默认限制已提高。编译、运行或字节对照失败也保存已完成 case 与阶段信息。

实际设备重跑 **v2 已通过**：Apple `metal-3`、明确非 fallback adapter，32 组共 **7,668 个原始 RGBA8 字节零差异**；其中半径 ≤512 与提取的旧生产 GPU shader 对照 **1,264 字节零差异**。1920/2048 域与直接 BigInt tap、独立正部三次积分有理 oracle 一致；这是先前被拒绝域的精确数学扩展，不是与先前不存在的 GPU 输出逐位对照。

完整 footprint 全 255 的 r1920/r2048、8192/16384 长 moment、负大坐标、透明边界、half-tie、末 partial band 和真实两轴 byte 中间边界均通过。实际最大 scratch（包含 per-band uniform）为 **1,966,592 字节**；真实 abandoned encoder 和覆盖提交的完成边界回收两项均通过。proof 输入文件前后 SHA-256 全部相同，浏览器错误 0。

公开 [数值及 SHA-256 摘要](byte-tent-summary.json) 仅包含计数、能力/预算、合成 case 的结果摘要和源哈希，不含像素、输入 words、真实文档 ID 或私人文件路径。独立 proof 的 16384 capability request 已记录；这不意味着生产默认 8192 已改变。

这只通过了独立 alpha 算子门。整份 FIG 的生产接入、画面、缓存、编辑、撤销、导出及延迟仍待验收；模块保持默认关闭，不由该算子结果自动启用。

## 生产 driver 接入：独立验收阶段

`WebGpuDriver` 现提供 `prepareByteTent()` 与 `encodeByteTentAlpha(target, source, options, availableBytes)`。只有 `VITE_DESIGN_BYTE_TENT_PREFIX === '1'`、`VITE_DESIGN_EXACT_CLAMP_PREFIX === '1'` 且 unmanaged 才可能采用；仍默认关闭。源与目标须有同 driver 私有创建记录、实际 RGBA8unorm 格式/尺寸/usage，禁止别名或替换 `Texture.resource` 后冒用旧证明。false 必须在分配、记录或目标证明变化之前返回；部分 encode 异常废弃整个 encoder 并禁止继续提交该帧，不能吞错后继续 scalar fallback。

全部 lease 纳入 `scratchBytes`，按实际 encoder 区分未提交与已提交状态。提交 ACK 不回收；checkpoint、finish、abort、park 仅回收对应真实完成边界覆盖的 snapshot。失败 fence 保留账本；未提交取消只丢弃已放弃 encoder 的资源。失败 park 的 promise 立即挂拒绝观察者但仍保留 rejected 结果，后续 revive 不将其当完成。device loss 或明确 device teardown 另行幂等释放，不使用异步 timer 在活动 renderer 下偷偷改变 scratch 账本。

CPU 定向检查单列为 **72/72**：新 `byte-driver-lifetime.test.ts` 31 项、既有 prefix 生命周期 2 项、image-table 生命周期 39 项。它们使用 mock device，覆盖拒绝域、完整计账、跨 encoder snapshot、submit/finish、失败等待、部分录制错误、取消/恢复、park 的立即拒绝观察/后续 revive/明确超时 teardown 及 device loss。`typecheck` 通过。此数不与前述模块 CPU18 项混为一次运行。

生产 driver 的实际设备脚本为 [check-byte-tent-driver.ts](../../frontend/design-client/scripts/check-byte-tent-driver.ts)。v1 在 Apple `metal-3`、明确非 fallback adapter 上通过：**11 场景、2,172 个原始 RGBA8 字节零差异**，其中 3 个双轴场景保留真实 byte 中间量化，另有 1920/2048 溢出、half-tie、透明边界和有限预算 partial-band。11 个像素场景采用 6 个 checkpoint、5 个 finish 边界，未完成 promise 时 scratch/lease 仍在，实际完成后全部归零。5 个错误 owner/格式/别名/预算/分数半径请求拒绝且目标 sentinel 不变。真实未提交取消、新 begin 恢复、已提交取消也通过；最大同时 scratch 为 **328,784 字节**。

2,172 字节包含 11 场景的 1,968 字节及恢复/已提交取消的 204 字节；拒绝和未提交取消的 sentinel 检查独立记录，不重复计入。读取来自实际 GPU texture→buffer copy 与 mapAsync，不是 CPU 渲染。测试拥有的读取 buffer 不经过 driver 的 rasterReadbackBytes 计数，所以该计数为零不能解释为没有回读。

本阶段实际生产 **device 上限为 8192**；adapter 报告的 16384 能力没有在此 proof 中请求，不能与独立模块的显式 16K 实验混用。运行前后 1144 项输入清单相同。原始 GPU 结果 SHA-256 为 `2a7d297179e7de928c2855e705a8c64b42b1475e7db0848ef13c959086200791`，计数与来源身份见[生产 driver 摘要](byte-driver-summary.json)。

**本次 `timingEnabled=false`。日志中的 queue wait 0ms 是未测，不能当成零延迟或性能提升。** 已记录的提交/等待次数只验证生命周期覆盖。

FIG renderer 已实现严格候选接入：单外阴影、整半径/整偏移、无节点内部 clip/mask/children，64 行逐段重建四相源，沿用原 mode23 byte resolve；H 只计算消费 X、保留完整 source Y，V 反移阴影 offset 并与原有限滤镜域相交。每轴仍实际写 RGBA8，后续保留原 mode6、逐相 sharp foreground、compose 和对象 opacity/blend 时序。每次 driver scratch 变化都同步 renderer 账本，异常废弃整帧后上抛，不抬旧 512 guard。

这是已实现的生产接入，**尚不是实际完整 FIG 验收通过**。最初的小场景 phase4 v2 观察到 2 次 byte pass；它与独立 driver 的 11 场景均不能代替完整 FIG、复杂缩放平移、合并后编辑/撤销/导出及实际延迟门。后续局部证据单列如下，不覆盖前述算子与 driver 历史。

## 祖先 clip 与实际 FIG 局部请求：后续独立阶段

实际 FIG 的首轮接入探针已定位：四相 incoming 祖先 clip 为普通 RGBA8 覆盖纹理，均不是 binaryCoverage；旧候选因此拒绝接入，随后碰到原 shader 的 512 guard。这是接入门不完整，不是通过放大旧常量解决的问题。

当前窄扩展只接受完整的四相、当前 owned/未释放的普通 RGBA8 祖先 clip，验证实际资源、尺寸和目标非别名。源四相重建、原 mode23 resolve、H/V 两次 byte 量化、原 mode6 和 sharp compose 都不读取该祖先 clip；它仅在每相原最终 merge 的原位置应用，保留对象 opacity、blend 与部分覆盖的先后顺序。节点内部 clip/mask/children 仍拒绝；没有按祖先 clip 外框缩小滤镜 source。新增流式用例共 **30 项**，所在五套定向检查 **106 项通过**；这是 CPU/mock 控制流检查，不当作像素执行。

phase4 独立实际 GPU **v3 的 40 场景**分域 gate 通过：583,680 个分量零差异。32 个证书准入场景与 unchanged wider crop 一致；8 个回退场景只对 unchanged legacy same-crop 证明一致，历史 wider-reference 的 888 个差异仍保留。新增的两个祖先 clip shadow 场景在不同 zoom 下使真实 byte-alpha 轴数从 2 增至 **6**；包括旋转的部分覆盖 clip，原 mode29 和量化顺序保持不变。此门没有旧 GPU 半径大于 512 的 scene 参考。

实际 FIG 的 **256 MiB、r1920、整偏移 Y=640** 局部请求 v3 已完成：UI3200%、DPR2，一个 64×64 请求、一次尝试，四个 68×68 非 binary 祖先 clip 均准入，真实执行 **2 个 byte-alpha 轴**，输出 4096 像素全部有限。峰值纹理计数 **53,422,152 B**，covered completion 后 byte scratch 与总 scratch 均归零，admission wait 0 次。实际 RGBA8 输出 SHA-256 为 `0393ae846f71c0dbd1f088d2a3eb3187a147d3a968cda96af738387b064d60e5`。

本次单个冷诊断请求耗时 **1164.5 ms**，graph 37.9 ms、finish 186.4 ms；CPU 队列完成等待 186.1 ms，其中读取完成 182.6 ms、初始化 3.5 ms。它包含 native/pipeline 准备与实际回读，不是干净输入延迟或 GPU timestamp，不能据此宣称整份 FIG 低延迟或持续缩放已通过。原始 GPU 结果 SHA-256 为 `fd0f161ca196d6fdfb676735fa896c80f5d81029899ead81823f35223af85bde`；1151 项输入运行前后相同，WASM 为前述 phase4 `40748786…fe1f`。

另已实际尝试 unchanged CPU `render_rgba` 对同一完整 screen window 做独立参考，但在产生像素前被原保护拒绝：`Combined filter dependency halo exceeds 2048 device pixels`（r1920 加 offset640）。**CPU 参考不可用，尚未建立该实际 FIG 整 scene 的 CPU 像素一致性。** 没有放宽 guard，也没有把这项拒绝计作通过。大半径独立整数有理 oracle、≤512 scene 的旧 GPU 对照和实际局部执行分别保留，不能互相替代。上述数值、能力、输入/结果/源哈希见[分阶段 driver 摘要](byte-driver-summary.json)；复杂实机画面、缓存、编辑、撤销、导出和整体延迟继续单列。
