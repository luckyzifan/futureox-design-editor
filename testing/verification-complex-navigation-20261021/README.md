全部 575 条路径包含 500 条闭合路径和 75 条开放路径。实际边引用 1284 个有效控制柄槽与 9730 个无效槽；源文件另有 26 个开放路径端点未被实际边使用的有效标记，不能把它们误算为丢失。新导入的所有锚点和有效控制柄坐标误差均为 **0**。

全部 575 条路径的 world affine 也与原始 frame/rotation/flip 层级独立计算结果一致，最大数值误差为 `5.55e-17`，比较容差为 `1e-9`。114 条圆形/圆弧全部通过；两列长度平方差与点积均为 0，距单位缩放的平方误差最多 `2.22e-16`。因此这份文件中的圆形缺陷来自丢失控制柄，不能归因于父级横纵缩放。

另有已完成的真实 WebGPU 像素证明：从新导入的原始小圆生成 1024×1024 透明选区，读取实际 GPU 像素，测量 720 个方向。固定径差门限为 1.75 物理像素；修复版最大误差 **0.875 px**、有效控制柄 9/9、非有限值 0。把旧的缺柄 network 作为真实 GPU 负对照时，最大误差为 **68.875 px**，门限正确拒绝。两次使用同一新 WASM；哈希绑定见 JSON。PNG 仅编码实际 GPU 回读，没有使用 UI 的 CPU PNG 导出替代 GPU 渲染。

这证明全部源路径的导入控制几何已恢复，并以一条原始圆形验证了实际 GPU 圆度；不表示全部 575 条路径都做了 GPU 像素比较，也不证明每个缩放中间帧无模糊、无白块或达到目标延迟。

**旧保存文档没有被自动修改。** 已丢失控制柄的 FD/SQLite network 不会因导入器修复而自动恢复，也不能凭图层名称猜测重圆化。应重新导入原始文件；若以后修复已有文档，必须核对原始控制数据与未编辑几何，再通过可撤销的编辑操作恢复。
