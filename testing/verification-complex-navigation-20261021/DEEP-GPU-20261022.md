# 117 / FIG 深度 GPU 诊断，2026-10-22

本轮仍在验收，**尚不能宣称连续缩放无模糊、无白块或达到低延迟目标**。当前代码的显示候选与默认产品路径分别记录；独立算子或 64×64 局部请求不能替代整份 Electron 的复杂输入、画面、缓存、编辑、撤销和导出检查。

## 已确认的等待来源

既有实际 CPU 火焰图显示 FIG 的同快照交互拓扑检查和主线程数值诊断占用明显；本轮分别加了不可变快照快速命中和缺失字段的提前跳过。诊断回放是 CPU 检查，不是 GPU 提速证据。队列完成等待单列，不能把 Worker idle 或嵌套 inclusive CPU 时间相加称作 GPU 执行时间。

117 原失败的 64×64 请求现在可由显式原生依赖证书编译。phase3 曾需要约 3658² 的图像支撑和约 2428² 的背景前缀；新 phase4 冻结 capture、只收紧真实读取域后分别为 3658×2478 与 2428×1248。不能只把 halo 除以二。实际 GPU 暴露了三种不同问题：

1. 已编码并释放到池中的大面仍受完成 epoch 约束；新 merge 必须先获得真实队列完成和回收，不能在同步 acquire 中销毁在飞资源。
2. 通用 paint 在初次计划之后惰性上传图像/字段；merge 需要按实际记账后的余量再次准入。一次假预算失败会触发整帧重试，并暂时关闭 prefix 加速，放大后续等待。
3. 256 MiB 下，小实色图形写入宽透明父目标会产生另一个约 89 MiB 的真实 live 样本面。这里没有可回收池，不能用更多 fence 或假定回收完成来解决。目标还要容纳后续兄弟节点，直接把其 rect 改为形状界会漏画；任何紧凑表示必须保留独立的后续绘制域。

## 精确算子和负例

- clamp prefix 实际设备 v3：20 组、3120 个原始 f32 分量零差异；17 准入、3 按原 shader 界拒绝。早期 half-ULP 期望和设备纹理尺寸失败均保留，不能改写成通过。
- byte-alpha integer-tent 独立模块实际设备 v2：32 组、7668 字节零差异。半径不大于 512 的 1264 字节另与旧生产 GPU kernel 对照；1920/2048 与两个独立精确 CPU oracle 对照，不能称作以前不存在的大半径 GPU 的逐位一致。其后生产 [driver 独立门](byte-driver-summary.json) 已通过 11 场景、2172 字节零差异及真实 checkpoint/finish/cancel 回收，仍默认双 strict flag 关闭。实际生产 device 为 8192，不能套用独立模块的 16K capability request；driver proof 计时关闭，0ms 表示未测。
- 原生 phase3 对过细 rotated backdrop 相位拒绝整份证书，保留同 crop legacy scene。此前 rotated/1.375 的 864 个原始 f32 差异仍是失败记录；不能用视觉近似容差覆盖 exact 证书失败。细节见 [采样相位审查](PAINTER-SAMPLING-PHASE-REVIEW.md)。
- phase3 小场景实际 GPU v2：32 组、466944 分量的分域 gate 零差异；24 个准入场景与 unchanged wider crop 逐位一致，8 个拒绝域与旧 same-crop 逐位一致。拒绝域的 wider-reference 888 分量差异仍单独保留。候选真实执行 16 次紧凑实色写入。v1 的新合成夹具存在 unreachable-node 错误，在 20 个已完成用例后失败；修正可达关系后重跑，没有改变 shader 或数值容差。
- [X-program 复用实际 GPU](image-x-phase-reuse-summary.json)：16 场景、33 窗口、2684664 个原始 f32 分量零差异，23 个拒绝控制通过。相关相位可复用为 2/1 个程序，最后一个 fraction 的 1 ULP 差异正确保留第 3 个；实际 117 样本仍是 4 个不同程序，不能把合成去重收益套给 117。

紧凑目标的第一次真实 117 256 MiB 执行仍失败。4 个有效覆盖面各为 1283×416、每面约 8.54 MB，完整 logical 域为 2402×2428；隔离组返回时恢复四张完整纹理，再次超出预算。诊断明确保留初次 prefix-on 与整帧 prefix-off 两次失败，不能把第一次 trace 误当成第二次的终态。小场景正确性通过不使这个真实内存门自动通过。
