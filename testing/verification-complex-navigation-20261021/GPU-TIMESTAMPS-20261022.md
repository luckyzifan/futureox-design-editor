# 117 GPU 时间戳的解释边界

`deep-117-phase4-band-gpu-timestamps-v1` 使用同一实际 117 区域、字体及 WASM，显式设置 `VITE_DESIGN_GPU_TIMINGS=1`。原始 GPU 输出仍为 `894dc6af14b7b75beef695a1e5aaf104c74f8c57610612a30d393fbfa02f3aa9`；256 MiB 内完成，单次冷请求为 3097.7 ms。

这次 `passTimings` 包含 57 个聚合组，所记录区间之和为 46884.4544 ms，远大于请求 wall time。它们不能相加解释成独占 GPU 执行时间，也不能据其排序宣称某个小 pass 独占了几秒。当前尚未保存每个原始 begin/end 与 submission 关系来求区间并集，不能把这份聚合记录称作已解析的 GPU 火焰图。

时间戳模式还会禁用现有 merged exact-filter pass，因此其请求耗时不能与不带该开关的呈现测量直接作为性能对照。CPU 火焰图、CPU 队列完成等待、这些 GPU 区间和实际输入到呈现 ACK 的延迟是四类不同证据。

另一个可独立确认的控制流事实是：117 的原始背景半径乘变换后为约 `1177.2149658203123`。原有核包分母为 149 bits，触发 `prefixRationalUnsupported`，在几何检查之前退出前缀快路。保持同相的实际采样几何本身可以准入。取最近 f32 半径会得到不同的、62-bit 核包；这将改变精确滤镜参数，必须作为独立显示档候选验证，不能偷偷写进精确路径。

原始 profile、GPU 输出、输入文档与计数日志保留在忽略目录。本记录没有建立显示半径候选的画质、低延迟、复杂交互或导出验收结论。
