# 整份拓扑 Sketch：悬浮蓝框和 3200% 旧瓦片

在 Apple M2 Pro、16 GiB、DPR 2 的 Mac 上，从项目的默认 Electron 桌面入口打开 119,392,711 字节的真实拓扑 Sketch。没有点击素材列表，也没有切换到单素材编辑页。文件的三个源页面分别包含 209、55、42 项。回放使用独立本地配置；真实素材及截图不随仓库分发。[逐项数据、相机和构建指纹](measurements.json)

**悬浮。** 在整文件总览从第一块素材移到第二块，再移到空白，两个独立的素材 ID 先后出现，空白处没有轮廓。再将相机移到第 116 项（从零计）“01-底座”内的标题上，普通悬浮命中“编组 4”，原地按 ⌘ 命中“浅色大屏底座素材”，松开恢复组；三个 UUID 与原 Sketch 图层树一致。三次动作的原生帧提交号均为 1。截图中两条轮廓所占的区域有 12,232 个像素随按键变化，松开后该区域逐像素恢复。底部工具栏的动画不计入素材区域，完整窗口差异也记录在 JSON 中。

总览原先只有素材的渲染表面，可编辑文档的命中测试看不到它们。现在目录提供即时的素材命中，已显示的原生场景按蒙版、裁剪、可见性、锁定、变换与绘制顺序查询对象。帧内可以命中子层，组优先整体命中，macOS 的 ⌘ 用于深层命中。文字在渲染时可以拆成多个片段；悬浮使用原文本对象和已解析的屏幕几何。源所有者变化、拖动、指针离开或过期回包都不能恢复旧蓝框。这个查询不重开文件、不请求更清晰的缩略图，也不提交 GPU 帧。交互依据：[Figma 的图层选择](https://help.figma.com/hc/en-us/articles/360040449873-Select-layers-and-objects)、[Sketch 的组内选择](https://www.sketch.com/docs/designing/layer-basics/grouping-layers/)。此处验收的是列出的交互行为。

**3200% 跨区返回。** 真实滚轮落点固定在第 116 项的同一世界坐标，放大到 3200%，跨到第 210 项，再返回。旧版在相机已经显示“清晰”时，1710 × 1856 的原生图像有 3,173,760 个像素与独立重开渲染不同，最大通道偏差 155。现在视口每次改变需求都会更新代次；不匹配的素材范围暂停绘制，迟到的结果只回收资源。高倍移动减少过小的瓦片，并在完整密度和采样相位吻合后交接。

本机默认桌面构建的回放，首次达到 3200% 后、快速跨区返回后、原地再停留 3.6 秒后，分别与独立进程在记录的同一相机渲染的结果比较：原生图像和窗口内容区域均为零差异。首次 3200% 自手势结束至完整原生画面为 301 毫秒，短暂划过远处后返回为 13 毫秒。另一次先等第 210 项远处的素材在 3200% 完全清晰，再返回第 116 项，完整原生帧用时 1.66 秒；返回和继续停留两次都与独立重开的相机逐像素相同。首次进入 100% 落点为 5.05 秒，从高倍缩回的其中一次为 1.31 秒。单次回放的清晰时间不等于连续输入帧率；本轮没有验证所有 306 项都能实时精修。

**已有整文件结果的边界。** 2% 最小倍率下，真实左键和中键都能平移 72 × 38 CSS 像素并返回。FIG 的另一次 20,082 节点文件回归中，合并引入的常驻浅灰框从 974 个降到 0，导入、2% 平移前、平移后三张原生内容图分别逐像素相同。在改为按源页面保留相对布局之前，同一拓扑文件固定的 62 项密集视口从 9.00 秒降到 7.23 秒，首块完整画板 867 毫秒。密集视口的瓦片日志显示纹理峰值从 902 MiB 降到 773 MiB：合成阶段曾保留被替换的目标纹理，现在合成后释放旧目标，四相采样保持不变。这不是整个进程的内存峰值，也没有把旧的 62 项区域当作新布局的同一视口。

**复现。** 使用[整文件桌面回放](../verification-overview-zoom-20261104/replay.mjs)，三个位置参数依次是桌面构建目录、原 Sketch 和新建输出目录。普通入口设 `OVERVIEW_PROJECT=1 OVERVIEW_GUI=1`。悬浮设 `OVERVIEW_HOVER=1 OVERVIEW_HOVER_DETAIL=1 OVERVIEW_HOVER_ONLY=1`。3200% 设 `OVERVIEW_HIGH_ZOOM=1 OVERVIEW_HIGH_FOCUS=116 OVERVIEW_HIGH_CROSS=210 OVERVIEW_HIGH_HOLD_MS=3600 OVERVIEW_SKIP_NEIGHBOURS=1`；加 `OVERVIEW_CROSS_WAIT_READY=1` 可等远处真正清晰后再返回。可用 `OVERVIEW_HIGH_POINT_FROM` 传入之前的报告固定落点。分别以 `OVERVIEW_ORACLE_FROM=<回放 report.json>`、`OVERVIEW_ORACLE_SEGMENT=high-3200` 和 `high-cross-return` 启动新进程。使用[截图和身份断言](verify.py)核对。首次运行可让桌面程序自行发现布局、生成缩略图；已有同源缩略图与布局时可用 `OVERVIEW_THUMBS`、`OVERVIEW_LAYOUT` 指定。
