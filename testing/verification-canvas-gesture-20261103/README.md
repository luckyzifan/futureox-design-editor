# FIG 松手、标尺导航与拓扑冷区实测

20,082 个节点的 FIG 单路径旋转在 GitHub 基线已经生成 `setTransform`。历史操作编译在这组回放中约为 0–0.1 ms。耗时较长的是随后应用操作时，Rust 又为整份文档核对一次节点句柄。另一个可复现的停顿发生在开启标尺后，移动相机会让参考线重新遍历整页几何。

本轮分别构建了原版、仅改历史、仅改辅助几何、两项合并四个版本。对照起点为 `1331e504`。最终代码 `3dfd20d8` 包含了上游取色器提交 `2883d1b6`。最终桌面标准构建的全部 2,522 项源码哈希、WASM 与原生 sidecar 均与交互回放产物相符。环境为 Apple M2 Pro、macOS 26.3、Electron 44.7.0、离屏硬件 WebGPU。各轮输入、构建、报告和日志摘要见 [measurements.json](measurements.json)。

## FIG 默认设置下的松手

同一原件、同一 Contacts / Phone / Icon 下的 Path、相同拖动与旋转轨迹。独立打开应用，按 A、B、B、A 顺序，每次打开做两轮同序动作，每格 4 次。下表给出中位数。最终就绪计时从浏览器收到 pointerup 到脚本观察到精确 GUI 就绪，包含采样等待。

| 阶段 | 拖动，原版 → 仅改历史 | 旋转，原版 → 仅改历史 |
| --- | ---: | ---: |
| Rust 应用历史操作 | 38.1 → 1.5 ms | 24.6 → 1.1 ms |
| pointerup 处理 | 79.2 → 39.4 ms | 47.0 → 23.7 ms |
| 松手到精确 GUI 就绪 | 225.1 → 190.2 ms | 249.2 → 214.2 ms |

全部提交均为 op-batch。新版本旋转的四个样本为 194.5–299.1 ms，最大值高于本组原版的 278.3 ms。每轮 commitValidate、commitShare、historyCompile、historyApply 对应数据中的 CPU 阶段 21、22、34、37。Rust 共享不可变文档元数据和节点键集合的身份，变换及其撤销重做可保留已有句柄。删除、插入、整文档替换和失败批次有独立回归，包括先删除再插入且总数相同的情况。

## 标尺与多选时的平移、反向缩放

参考线沿用画布已经生成的场景和祖先链。智能多选读取同一份几何及父节点，单纯移动相机可以沿用世界坐标。以打开标尺的 FIG 比较仅改辅助几何的构建，各录两次相同轨迹。每次含 96 个真实滚轮输入，按两次测量分别列出结果。

| 操作 | 原版相机跟随 P95 | 仅改辅助几何 P95 | 原版匹配数 → 候选匹配数 |
| --- | ---: | ---: | ---: |
| 平移 | 49.6 / 47.6 ms | 9.5 / 9.3 ms | 96 / 96 → 96 / 96 |
| 快速反向缩放 | 48.3 / 46.3 ms | 19.4 / 20.0 ms | 61 / 57 → 67 / 63 |

每个输入只匹配下一个输入到达之前首个有相同相机的浏览器采样帧。未匹配的输入单列。仅改辅助几何的两轮导航均未观察到 50 ms 长任务，最终合并版缩放另一次观察到一个 51 ms 长任务。选取两个真实画框后，脚本确认两个智能选择手柄均已生成。最终合并版平移匹配 96/96、P95 9.2 ms，缩放匹配 74/96、P95 19.7 ms。这里没有测量物理扫描输出。

## 三份原件与高倍缩放

| 文件及目标 | 拖动松手 | 旋转松手 | 像素及历史 |
| --- | ---: | ---: | --- |
| FIG，Contacts 图标 | 见上方四次对照 | 见上方四次对照 | 按住、松手与 fresh 内容平面零差异，原版和最终版对应平面也相同 |
| 117.sketch，固定图形 | 71.7 ms | 113.0 ms | 按住、松手与 fresh 零差异，此目标未复现拖动黑影 |
| 拓扑素材.sketch，“4”双内阴影 | 233.5 / 235.3 ms | 1,210.8 / 795.6 ms | 本轮按住、松手与 fresh 零差异 |

三份原件都跑了连续平移、拖动、旋转和反向缩放，另起应用检查按住、松手和重新加载后的整张内容平面。三份文件、两种编辑动作的完整 authored JSON 在 Undo 和 Redo 后都与对应原状态逐字节一致。拓扑旋转另有一次历史回放差一个绿色码值，保留历史记录。精确像素检查与计时独立。

拓扑计时使用“先平移，再拖动、旋转、缩放”的相同顺序。`2883d1b6` 父版本的重效果拖动为 253.0 / 234.0 ms，旋转为 1,343.5 / 1,292.4 ms。最终构建的一轮旋转匹配到 19 个工作线程姿态请求中的 4 个，另一轮的 2 个请求均未匹配到单独回执。各场景 100 ms 精修和对象拖动可见 P95 33 ms 仍未通过。

完整拓扑源为 124,447 个节点、306 个根。从打开到本轮第一个可用视口为 36.15 秒，其中原生打开 9.30 秒、完整快照 11.94 秒。按原有截图口径，相同相机下的快速缩小仍有 24,542 个过渡像素三通道均 ≥248、停稳后至少一个通道 <200，此次对照两版相同。定点平移与之后的反向缩放截图均为 0。

模板二在 3200% → 125% → 950% → 40.4% 四个目标倍率都取得当前相机的精确就绪，耗时分别为 2.10、1.05、1.63、4.13 秒。3200% 的 855×960 内容平面与既有全密度分区参考逐像素相同。完整源的流式首屏、本轮未测的 600 次导出、全 G5 和跨平台 HDR 仍待验收。

## 验证入口

本机运行 `node frontend/design-desktop/scripts/build.mjs --fast --out-dir=<fresh-output>`、客户端 TypeScript 检查、46 项画布和辅助界面回归、18 项前端历史回归，以及 Rust 的 30 项 graph_api 和 6 项 snapshot 回归。字体测试使用仓库要求的 fonttools 4.61.1 和独立临时目录。

解压[本轮原样保存的三个回放脚本](replay-scripts.zip)，在仓库根目录启动，并为输出指定尚不存在的绝对路径。GUI 计时使用 `actions.mjs <原件> <新输出目录>`，指定 `QA_WORKSPACE`、`QA_PRODUCTS`、`QA_OFFSCREEN_INPUT=1`、`QA_ISOLATED_INPUT=1`。FIG 固定图标使用 `QA_DOCUMENT_NAME=Document QA_PLAIN=1 QA_DEEP_PICK=1`。计时用 `QA_TIMING=1 QA_RELEASE_IMMEDIATE=1`，像素和历史对照另开应用用 `QA_CONTENT=1 QA_FRESH=1`。多选检查和完整源缩放链分别使用 `multi-actions.mjs` 及 `full-zoom.mjs`。每轮保留脚本哈希、run ID、退出状态、产物与原件哈希，原始轨迹及图片随测试机记录保存。

完整源冷区和倍率链使用同一原件及模板二，运行时设置 `QA_FULL_SOURCE=1 QA_ROOT_NAME=模板二 QA_PAN_DX=-225`。应用与输入隔离参数同上。

四动作回放用 `QA_CASES=pan,inside,rotate,zoom`，两轮 FIG 松手对照用 `QA_CASES=inside,rotate QA_REPEAT=2`。117 的目标设为 `QA_TARGET_ID=98906AEB-08B4-49AA-9173-C99496434AAE`。拓扑使用 `QA_ROOT_NAME=4 QA_ROOT_ID=59AD38D3-0BFE-487B-AB68-DB970F9A0325 QA_TARGET_ID=6F3B0C9E-214F-45C5-AB39-3A84457564F3`。

前一轮未采用的实验也保留了结果。合并四块精确瓦片后，修正回退条件的版本在重效果旋转上仍用了 878 ms，同序基线为 735 ms。提前省略只读快照的导出元数据得到完全相同的 300,408,797 字节，但两次快照耗时均未改善。
