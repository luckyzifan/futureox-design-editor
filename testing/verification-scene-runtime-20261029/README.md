**逐模块重构：模块1，节点索引存储底座（2026-10-29）**

用户要求：以完整拓扑素材为主样本，按模块推进，以单元/模块测试为主，最后整合阶段才操作Electron做真实回归。本轮没有启动应用、操作鼠标键盘或执行GPU验收。

**已经落地**

- 原生Rust新增不可变场景包，沿用现有Document/Node模型。节点记录、固定长度磁盘索引及校验树分开存放；格式属于内部派生存储，不改变FD、Sketch或FIG格式。
- 按ID读取时，在磁盘索引上二分定位并验证对应记录，不扫描或解码其他节点。索引使用独立的校验树，打开后文件被修改也不能用错误索引替换节点。
- 元数据延迟读取。页面、字体、原格式保留数据不会因单个节点查询而被完整解析。显式读取元数据时仍读取完整元数据块，后续资源/页目录模块再细分它。
- 写入逐条进行，索引校验树逐层使用有界缓冲构建；读取不把全部索引载入内存。随机查询当前为O(log² N)小块索引读取，节点载荷为按需读取；完整消费者使用顺序扫描和O(log N)校验状态。
- 返回的描述符绑定文档、代数、节点数、文件长度及内容证明。取消、损坏、错误代数、非完整文件都不能发布节点为成功结果；写入不会覆盖既有文件。
- 现有源转换缓存已经使用新格式。原有缓存损坏后从源重建、版本失效、会话清理规则保持不变。底层场景包关闭后可重新打开；跨会话目录持久化还属于后续工作。

实现：[scene_store.rs](../../design-studio/crates/design-kernel/src/scene_store.rs)、[转换缓存适配](../../design-studio/crates/design-desktop-backend/src/large_document/window_cache.rs)。文件清单、前后哈希及源码身份在[module-1-manifest.json](module-1-manifest.json)，本轮修改前内容在[preimage](preimage/)。没有重置、提交或覆盖用户原有其他改动。
