**模块3：将需求视图接入实际原生渲染编译（2026-10-29）**

用户最初要求：继续模块2，把视口需求真正接入编译，以完整下载目录拓扑素材做单元和模块测试，最终整合时才启动 Electron。下文为该模块阶段的 CPU 记录。用户随后明确要求真实桌面验证；新发现的缓存回退、修复及仍然失败的端到端耗时见[Electron 续轮](../electron-final/README.md)，不得用下面的模块通过覆盖该真实失败。

**已经接入**

现有调用链保持 `NativeSourceSurface → RenderKernel.compile_gpu_packet → NativePreparation → Rust Preparation::request`。仅当 lane 持有宿主授权的源描述符时，原生 `compile_gpu_packet` 自动进入 `source_compile::Runtime`；不是新增一个无人调用的诊断接口。普通文档和不支持的请求继续使用原完整编译器。

- 目录直接利用已验证源的权威布局结果，不再额外读整份场景包、建立第二个 Engine 重做布局。选中记录从已解析图复制，保留组件、布尔路径、字形派生 ID 与私有路径。原始 children 也保留，避免布尔节点的非绘制子节点在旧编译器查询时缺失。
- 编译器收到只读投影，节点图只包含当前需求；不会通过复制完整 Document 再删除冷节点来生成投影。保存、编辑、导出、完整回退仍使用原完整 owner。投影中省略的作者元数据和字体声明不代表源数据删除；真实字体资源由已有 Fonts owner 提供。
- 完整页面的效果边距、背景标志及采样谓词单独传入，防止删除屏外节点改变现有捕获、裁剪或四采样决策。边距仍由原 MarginIndex 按原顺序计算，同一源/缩放可直接复用标量，平移不重新读取所有效果记录。
- 视口输出需求、舞台边界贡献和整页准备边距分别处理。屏外边界贡献者不自动触发整段背景前缀。实际编译完成后、传输资源 ID 分配前，根据真实 scene extent 再检查全部生产者；需要扩展时重建一次，不能收敛则使用完整路径。
- 上述读取范围缩减只用于已核对的 legacy subpixel canvas 契约：生产者输出必须覆盖实际场景读取域；未知输出保守保留。新请求策略、导出剖面、动画、径向读取、非中性舞台、页面根蒙版、预算不足及场景外背景证明等继续完整编译，不修改其既有精度或分配策略。
- 同一个资源 owner 在按需、完整、取消和失败之间移动，不在相同 scope 下重新从零分配资源 ID。投影变更撤销精确请求缓存，修改文档撤销整个源投影入口，防止投影计数与原文档 revision 偶然相等时复用旧包。实际编译统计返回调用方。
- 只保留一个编译需求视图，不累计所有访问区域的并集。全页 margin 占用计入原共享编译缓存预留，切换路径释放另一条路径的可选几何缓存；不提高 GPU、路径、纹理或包预算。

**仍保留的完整 Document 依赖**

完整 authored/resolved 源仍驻留，作为投影的已解析记录来源和所有权基准。本模块不是磁盘冷数据换入换出，不是首屏 O(视口)，也没有解决完整模型初次加载、布局或目录建立成本。当前按素材子树组织投影；首次遇到新缩放仍可读取完整源里的稀疏效果索引。

本轮取消的是支持域内几何编译对完整节点图的直接依赖，尚未取消完整源的驻留。普通 `load_document` 小文件路径尚未统一到这个存储/需求入口。后续需要把已解析记录和目录做增量/分页持久化，统一大小文件调度，并处理目前完整回退的域。
