# 拓扑 Sketch：重构前测试用例

原件为下载目录的 `拓扑素材.sketch`，SHA-256固定在 fixture.json。普通导入、全源显示、局部编辑是不同路径；记录实际进入的模式。编辑/保存只使用隔离工作区或副本。不要覆盖原件、关闭已有工作窗口或通过开启实验选项让测试通过。

## 自动化基线

固定800×600 CSS、实际DPR，当前默认策略，启动真实native准备器和WebGPU。每例新建Surface，只有该例内部的导航保留缓存。全部效果和源对象保持原样。

| ID | 动作 | 可执行断言与观测 |
| --- | --- | --- |
| cold-local-400 | 全源首次载入，中心(878,278)，400% | 源306素材/124447模型节点；首块、完整ACK、载入、compile/graph分别记录；当前相机、DPR、实际像素 |
| steady-100 | 新Surface，100%静止 | 完成后立即请求GPU读回；排空并静止300ms后再次读回；两个hash相同、无意外透明 |
| fractional-125 | 125%，相机额外平移(0.25,0.375) CSS像素 | 原生密度、最终相位、相机与图像尺寸；不能拿整数相位缓存冒充 |
| cold-detail-3200 | 新Surface，3200% | 当前高密度像素确实完成；明确区分首次载入和高倍编译 |
| fresh-target-reference | 新Surface，950%静止 | 作为同层独立重建参考，保存完整像素hash |
| motion-fresh-target | 400%预热，32步放大/反向至3200%，最终停在950% | 最终目标不同于已预热400%；与950%重建参考相等；记录运动最大放大倍率与停手到清晰 |
| motion-return | 相同动作，最终回400% | 与首次400%像素相同；缓存返回延迟单列，不能替代新目标测试 |
| pan-return | 400%下正反向平移，最终返回 | 返回像素相同；记录取消、旧像素放大、后台排空和可见rAF停顿 |
| overview | 缩到整图适配，完整源仍在同一画板 | 所有可见瓦片必须完成；300秒未完成保持FAIL及部分结果，不推算总耗时 |

所有完成例必须在对应完成回执中证明native coverage与相位，不能使用后来的高质量统计替换第一次回执。读回本身可能等待GPU，不能据此宣称该回执时刻已物理上屏。这里的hash对照测一致性；字形是否像Sketch一样清楚另测。

## 用户在完整编辑器中的测试

自动化以上使用生产Surface，但不经过真实鼠标、选择框和编辑事务。以下是完整应用的单独测试表，当前未运行项必须保留NOT_RUN。

| ID | 操作步骤 | 预期与必须保存的证据 |
| --- | --- | --- |
| GUI-01 冷打开 | 新启动隔离应用，导入原件，适合整图 | 导入/快照/第一块/全视口分别计时；截图和版本；全部素材保留，未完成不能标清晰 |
| GUI-02 未访问高倍 | 选定同一个图标，从400%连续放大到3200%，停在那里 | 记录最后输入到新密度画面、最大旧帧持续、逐帧画面；不能先回原视口再取完成时间 |
| GUI-03 反向缩放 | 尚未清晰时立刻反向，最终停950% | 最新目标获服务，无旧相机跳回；取消工作最终停止；950%静止参考一致 |
| GUI-04 细线与文字 | 固定可见文本/细线，100%→125%→200%；每档停到完成 | 保存GUI图、内容读回、DPR、Canvas/CSS尺寸和相机；与同字体/同层独立参考对照，不能把抗锯齿软边一概当错误 |
| GUI-05 分数平移 | 在125%横纵缓慢移动，再回原点；更换窗口尺寸 | 无瓦片接缝、重复采样发软、丢线或错误清晰；整数与分数相位分别截图 |
| GUI-06 对象跟随 | 在可编辑素材内拖动对象，再反向拖动 | 内容、紫色选择框、命中位置和属性值同一有效姿态；旧内容不被“框很流畅”掩盖 |
| GUI-07 旋转与缩放 | 旋转后立即反转；resize后继续拖动 | 保存动作视频、最后输入与最终像素；不残留原始姿态/透明缺口 |
| GUI-08 连续编辑 | 拖动后改填色/效果，撤销、重做，再拖动 | 显示当前revision；一次编辑的撤销边界正确，旧缓存不得复活 |
| GUI-09 换源取消 | 大视口绘制中切页/切文档，然后返回 | 旧源晚回不覆盖新源；资源归还，返回内容正确；源加载和渲染取消分开 |
| GUI-10 保存重开 | 修改隔离副本，保存、关闭该副本、重开 | 对象参数/资源/源所有权一致；重新渲染像素正确；下载原件hash不变 |
| GUI-11 导出 | 对选定图标导出1/2/3倍PNG，修改后重复 | 尺寸、当前revision、效果与透明度正确；这不是完整100图标矩阵 |
| GUI-12 反复导航压力 | 固定GUI-02/03/05动作重复10轮 | 首末轮资源峰值/稳定值，晚回、device错误、缺块；不通过扩大预算掩盖问题 |

全源概览若只能双击进入局部工作集才可编辑，应记录“全源直接编辑未实现/不可测”，不能拿局部编辑通过替代。普通小文件的ProgressiveSurface导航同样需独立测；本源Surface测试不能覆盖它的DPR1预览策略。

## 数据填写与判定

每条记录构建/source digest、文件hash、设备、后端、DPR、窗口、默认开关、动作、首像素、最后输入到清晰、旧帧最长持续、最大放大倍率、后台排空、错误与资源峰值。缺字段写UNKNOWN。

非预期空白/透明、旧内容、错误相机、已完成图像随后变化、源对象缺失均FAIL。可见渲染区间>250ms rAF间隔沿用现有停顿门；它不等同输入到像素延迟。绝对交互时间目标尚未确认，本轮只测分布，G2延迟BLOCKED。新算法的性能A/B必须同构建条件、交替至少三对，保留冷启动及失败样本；同层精度不得退化。

## 测试本身的负对照

report-contract.test.mjs拒收：旧缓存冒充新目标、晚到质量统计、缺失数值、透明洞、静止像素漂移、错误相机/DPR/尺寸、缺场景、重复case、未排空、时间戳改写、源缺失和CPU替代。provenance.test.mjs拒收产物变化或缺清单。这些测试验证报告不会轻易给假PASS，不是产品画质验收。
