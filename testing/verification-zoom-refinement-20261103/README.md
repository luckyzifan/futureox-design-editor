# 《拓扑素材》「模板二」的高倍精修

在 Apple M2 Pro、Electron 44.7.0、WebGPU、Retina 2× 的项目桌面版中，打开原始 Sketch 文件的浅色页「模板二」。同一相机从 1600% 放到 3200%，全分辨率分条计算的参考构建耗时 5,362 ms。默认桌面构建的五次独立进程回放均在一秒内完成。另用新桌面配置、首次打开该文件复测了一次。时间从提交缩放输入起算，包含瓦片编译、绘制和画面交接，文件打开耗时另计。[原始测量、源文件及产物哈希](measurements.json)

| 缩放比例 | 参考构建 | 五次中位数 | 五次范围 | 新配置复测 |
| --- | ---: | ---: | ---: | ---: |
| 400% | 2,402 ms | 573 ms | 550–582 ms | 678 ms |
| 950% | 2,470 ms | 474 ms | 455–485 ms | 520 ms |
| 1600% | 2,590 ms | 388 ms | 377–399 ms | 413 ms |
| 3200% | 5,362 ms | 549 ms | 534–592 ms | 726 ms |

## GPU 工作量

3200% 的一次详细回放中，参考构建累计编码约 31.92 亿个像素，绘制 17,002 次。新构建累计约 1.42 亿个像素，绘制 796 次。盒式滤波绘制由 3,179 次降到 0。统计窗口内参考和候选分别收到 19 和 20 个瓦片事件，计数是这次输入的累计工作量。图层数量、最终屏幕像素数和中间像素访问次数分别计量。

高倍源文件视口中的每块瓦片独立检查绘制顺序。只有后面的普通不透明图层在四个原始采样相位都完全覆盖整个目标，且前面的绘制、混合和图片取值满足范围检查，才可以跳过被遮住的图层。原件中一个被完整遮住的大半径高斯模糊占用了大量计算。相邻瓦片还可以省掉被挡住的渐变。遇到临时表面超出预算时，内核可以在原采样密度下分条计算高斯，同一源、修订、倍率和准备窗口内复用成功的调度选择，各块重新验证输入。

对已经有遮挡证明的源瓦片，普通两色线性渐变只有在同一插值区间内才使用四角参数。四个抗锯齿相位分别调用原内核采样。跨色标、钳位边界、退化变换、HDR 和精确输出走原有路径。每个像素的轮廓覆盖、渐变颜色和混合仍由原绘制程序计算。

## 像素与验收

每次在新相机产生绘制状态变化、相机投影结束并报告清晰后，从原生画布读取全部 1710 × 1776 物理像素。计时在 PNG 读回之前结束。400% 与 3200% 的输出与全精度参考逐像素一致。950% 与 1600% 各有一个像素的通道相差一个 8 位色阶。原始图件、浏览器配置和用户恢复记录均未发布。

显式开启半尺寸高斯工作面的对照曾把「模板二」950% 的精修从约 2.4 秒降到 2.0 秒，3200% 仍需约 4.6 秒。另在有可见模糊的「数据名称」边缘，隔离试验省略一条已禁用的描边后，半尺寸路径在 3200% 的 256 × 192 输出上从 28.2 ms 降到 25.7 ms，黑白底合成最大编码误差约 0.000054。交付构建保留原有模糊半径及原密度。厂商资料可核实 Sketch 曾用遮挡关系省略离屏绘制，Figma 的 WebGPU 文章将计算着色器优化模糊列为后续方向。[Sketch 工程文章](https://www.sketch.com/blog/tech-talk-how-we-made-the-mac-app-faster-with-improved-rendering/) · [Figma 工程文章](https://www.figma.com/blog/figma-rendering-powered-by-webgpu/)

## 另外两个页面

同一修改在「控件 / 数据名称」中心的 3200% 仍需 4.76 秒，参考为 5.08 秒。该视口仍访问可见效果，累计上传约 1.32 GB 的材质参数。「深色 / 拼搭样式二备份」中心的 950% 约为 10.26 秒，3200% 在候选和参考构建中均触发浮点图片内存预算。这两个视口仍需独立优化。
