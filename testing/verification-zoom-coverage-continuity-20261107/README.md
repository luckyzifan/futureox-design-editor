# 连续缩放大面积空白：覆盖连续性（2026-11-07）

## 故障

最新 main（`083a5743`，含缩出覆盖保留、手势期导航、缩出密度播种）上，滚轮/触控板无论快慢，缩放过程中仍出现大块空白、截断。空白会持续到整层目标瓦片完成，不只是一两帧的渐进替换。

## 根因（已在代码路径上核对，不是色值修补）

三条近期改动没有打到发布条件：

1. **缩放只提交“一整层同密度瓦片”。** `NativeSourceSurface.paint` 在目标格子未齐时直接 return，画面停在上一张位图上，由 CSS 缩小。新露出的世界区域被 `CameraReprojection` 涂成纯色块。已在缓存里的更粗总览/低密度瓦片不进入这一帧。编辑器 `ProgressiveSurface` 同样只激活完整粗层、单张视口预览，或上一帧居民；`overview` 瓦片只进 1 MiB 的 CSS 图集，一次拷一张，不进 GPU 合成。
2. **缩放比一变就把正在画的瓦片当成过期取消。** 飞行中的瓦片只在相对密度 0.5–2 倍内保留；缩出超过这个窗口，或松手进入精确相位时，正在补洞的一层被 `workQueue.demand` 取消。快缩放因此永远等不到能盖住新视口的像素。这是“为了帧率丢掉覆盖”，不是覆盖策略。
3. **缩出播种只降低下一次光栅的密度，不改变“齐了才显示”。** `b19f3b46` 的 `SourceQualityLadder.seed` 仍然要等该密度的整组瓦片返回。边角瓦片排在中心之后，所以洞在队列尾部才被填上。

`083a5743` 把缺口从 `#fff` 改成 `#f5f5f5`，颜色接近画布，没有增加像素。

假设里“一改缩放就把全部瓦片作废”不成立：缓存键没有在缩放时清空。空白来自**不把已有的更粗覆盖画出来**，以及**取消那些本来会补洞的在途瓦片**。

## 本轮修法

覆盖栈，而不是再加一条只在某个方向生效的特判：

- `coverage-stack.ts`：`selectCoverageUnderlay` 取仍能涂到未绘制视口像素的最粗居民（总览或低密度），画在更锐的一层下面。`selectCoverageStack` 只在粗层加细层的并集盖住整个视口时才允许发布；盖不住就继续留着上一张图，不交一张有洞的帧。
- `retainInFlightTile`：缩放比例变化本身不是过期。视口里还有它能画上的洞，就留着；洞已被居民涂满、且它不是当前键或邻近密度时才取消。缩入时大于 514px、又不补洞的整屏捕获仍然取消，避免占住唯一的光栅 owner。落定后，显示背书已经盖住视口时，四倍更粗的在途瓦片仍按原 `VITE_DESIGN_SETTLED_SOURCE_PRIORITY` 让路。
- 连续缩出时，缺失瓦片先排未覆盖区域（`prioritizeUncoveredTiles`），边先于中心。
- `ProgressiveSurface` 在当前帧没有盖住视口时，把已就绪、同一设备上的更粗瓦片标成合成项。合成器原有的按层/按 zoom 遮挡不变，精确相位完成前不算终端质量。

没有改预算、精确导出、落定密度或 `navigationPreviewDensity`（普通倍率预览仍是物理 DPR）。没有新的实验开关。

## D 复测（2026-11-07，8% 粘贴板）

117.sketch 缩到 8% 时，画板大约 153×85，视口比页面大。居民瓦片只覆盖画板，画板外没有可合成的粗像素。平移不提交新帧，`data-source-coverage-extend="pan"` 不会出现，新条由 `CameraReprojection` 涂成 `#f5f5f5`。

现在：视口伸出页面时排一张粗页瓦片，范围是当前视口再加一整屏，并按视口格子量化，所以平移至少四分之一视口仍落在同一张上。这张瓦片一盖住视口就发布，不必等画板格子齐。平移时再按新相机合成它，提交时写上 `data-source-coverage-extend="pan"`。条带是这张瓦片的像素，不是缺口 div。

再跑 D：117.sketch，打开大型 JSON / Sketch，缩到 8%，手势平移至少四分之一视口（约 230–250px）。新露出的一侧应是这张粗页瓦片，而不是整条 `#f5f5f5`。`.native-source-content` 上有 `data-source-coverage-extend="pan"`。停下后仍应收锐。

## D 复测（2026-11-07 平移条）

平移（含缩放过程中平移，以及缩放出更粗覆盖之后立刻平移）把 `continuousZoom` 清掉，并且任何姿态变化都 `quality.reset()`，缩出播下的粗密度被丢掉。新露出的一条不进覆盖栈。已发布的画面是裁过的视口位图，CSS 一移，条带就由 `CameraReprojection` 涂成 `#f5f5f5`。晚到的覆盖帧还因为实时相机会变而被丢掉。

补上：`coverageBeyondBacking` 在新视口被居民瓦片盖住、且画出旧位图以外的世界时就提交这叠瓦片；纯平移不重置密度梯子；非缩入的移动先补未覆盖边；平移后才到达的同一倍率覆盖帧用 `acceptTranslatedCoverage` 收下，再投影到最新相机。缩放变了的帧不收。

再跑 D：密文档上先快缩出到能看见更粗画面，按住平移（或缩放的同时平移）穿过至少一条视口宽度的 1/4。新露出的条应是已有粗瓦片的内容，而不是一整条 `#f5f5f5`。停下后仍应收锐。提交平移帧时 `.native-source-content` 上就有 `data-source-coverage-extend="pan"`，不必等回执。回执按这一帧自己的瓦片 id 核对，不跟手势里更新的下一帧比较；所以连续平移时上一帧的粗覆盖仍会换上，而不是整段手势都被丢掉、灰条留到松手。位姿已经静止但位图还停在旧相机时，也会再走覆盖栈。

## SCORE（桌面人工/自动化都可跑）

在一份密文档（多画板、含模糊或图片）上：

1. 停在能看清内容的倍率，快速滚轮放大穿过至少四档，再快速缩小回起始倍率。中途大块纯色区域不得超过一两帧；允许先糊后清。
2. 同样路径用慢速滚轮/触控板再走一遍。松手后应变锐，变锐过程中不能先挖掉已经在屏幕上的区域。
3. 缩放过程中拖动画布（边缩放边平移）。新露出的一条应出现已有低密度像素或很快补上的瓦片，而不是一直留白直到整屏重画完。
4. 停下约一秒。画面应回到当前相机的精确相位，不停留在总览糊层，也不报画板失败。
5. 失败时看 `data-coverage-underlay`（编辑器）和是否整屏只剩 `#f5f5f5` 缺口。underlay 大于 0 仍长时间空白，才是这条修复没接上合成器。

## 相对 Figma / Sketch 仍开放的流畅度

- Mac 桌面 Figma 有完整 mip，相机每帧在 GPU 上重采样，缩放中几乎看不到洞，锐化是原地替换。这里只重用**已经在显存里**的更粗瓦片，不预先建整页金字塔。冷的大幅度缩出要等第一张粗瓦片；重效果页这张瓦片本身仍可能是秒级（既有开放项，拓扑冷视口约 35s、反向缩出就绪约 9.4s 没有在本轮用真机重测）。
- Sketch 的 `tileLevel` 在一个桶内不重光栅，单元格取已有最细瓦片。本仓库落定后仍会要当前相位的精确格子，停手后的精修时间没有变。
- 编辑器导航预览捕获仍是物理 DPR 整帧，连续缩放时仍可能被更宽的目标取代。洞靠已有粗瓦片补，不靠把预览降成 1x。
- 平移预览的缺口着色器仍是不透明白。缩放路径在居民瓦片能盖住时不再依赖它。
- 仍然只有一个光栅 owner。留下补洞瓦片会让下一级密度晚一个批次。这是覆盖优先于“取消一切来追帧率”。
