## 快速移动时的内容

浏览器在现有显示额度内保留最多 1 MiB 的页面预览，只在当前帧实际缺失的矩形内显示，同页同修订的 GPU 像素就绪后逐块接替。不同修订、设备或显示条件不能复用。编辑文档的小页先建立一张完整预览，大页使用区域任务。完整源的屏外任务在可见请求完成后才开始。曾试过在可见请求前预取八倍视口，拓扑原件在该候选上超时，未采用。嵌套或重叠选择使用原图层渲染；可从屏幕提取的独立对象还需校验源矩形和移动后的矩形。

## 重效果和 FIG 编辑

四相位渐变字段保留原采样参数的位表示。未改变的材质在同一私有资源上复用，旋转改变了参数时才重新构建相应字段。普通 SDR 的 WebGPU 驻留交互才会进入这条路径，`VITE_DESIGN_GRADIENT_PHASE_FIELDS=0` 可退回。新编码继续受原字段缓存、表面预算、取消和 GPU 完成边界约束。

拓扑“4”的真实双内阴影路径在这版基线的暖拖动采样为 44,529,792 B/次，约 60–62 ms 构建。优化后为 65,536 B/次，约 0.4–0.8 ms；非零暖旋转样本为 1.29–1.43 MB。历史记录的约 278 MB 来自另一构建/交互上下文。Apple Metal 3 对真实字段和合成用例执行了 56 组原始 WASM 参数字逐位对照，包含横纵线性轴的全部四相，全部零差异。暖拖动一次完整采样仍约 235–264 ms，后段 GPU 完成等待是剩余成本之一。

FIG 使用同一原件、目标和动作顺序，每种目标在两份构建各重复两轮。表内为 pointerup 到精确 GUI 就绪的观测范围。普通目标是 Contacts/Phone/Icon 的可见 Path。布尔目标是 Cart icon 的 Path；只有重新求解完整局部布尔轮廓并证明结果未变，才允许空页面损伤。布尔轮廓改变的反例会退回完整处理。两组都检查了撤销。

## 3200% 与像素所有权

从该拓扑原件捕获的 124,447 节点原生场景中，Ellipse 16 在 64 倍设备采样密度的单个 514×514 输出原本要分配 4658×4658 表面，超过 16,777,216 像素限额。现在仅在普通 SDR 显示瓦片的原编译因该限额失败时，以同一相机、原半径和原四采样重试分区高斯。关闭区域策略仍能复现原限制，不使用缩小的效果网格，也没有提高预算。

原失败视口 20/20 块拒绝；分区请求 20/20 成功。真实 Electron 默认配置进入 3200% 后能得到精确回执并缩回总览。一次计时约 2.87 秒。最终 **855×960 整个内容平面** 与显式全密度分区参考逐像素一致，排除了界面提示条。CPU 画板另用绿色源瓦片验证了实际画布内容。CPU 压力预览保留实际采样密度，失败的块不冒充精确内容。小尺寸精确 PNG 的超限效果会返回错误；旧版曾输出与移除模糊后完全相同的 PNG。

可见 FIG 图标和 117 的拖动、旋转，以及拓扑“4”的拖动，held/settled 对 fresh 内容平面均为零差异，完整 authored Undo 恢复。拓扑单独旋转的 held、settled 与 fresh 各有 **1 个像素的绿色通道相差 1**；相同场景在基线复现，候选与基线各对应平面逐像素一致。部分旋转没有得到最后匹配的 resident 输入 ACK，独立像素对照不能代替该延迟门。

## 验证边界

桌面标准构建及类型检查通过。原生位姿组 33 项通过、1 项既有忽略，字段编码 3 项和区域高斯 5 项通过，另有精确 PNG 反例。浏览器侧最终相关定向检查 94 项通过。较广 GPU/编辑回归有 2038 项通过、7 项 todo、1 项失败，失败项为零尺寸选框预期 9 个手柄、实际 8 个，已在未改的 GitHub 源码独立复现。未修改该项工具行为或测试期望。
