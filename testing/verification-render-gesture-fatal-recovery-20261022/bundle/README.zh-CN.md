## 实际修复

仅在移动手势仍活跃时，原生预览若在指针停止后异步 fatal 失败，不再依赖下一次 pointermove 才处理：在当前文档、页面、会话、选择和输入序号仍匹配时，一次性把最新的绝对 patch 转交原有 Editor 事务。同步抛错也等 apply 返回、最新待处理 patch 已发布后再通知，避免丢失本次移动。

交接先结束失败的原生姿态作用域，再走已有编辑路径，防止重入导致重复移动或额外历史项。保留提交、撤销、重做与取消行为；结束、取消、提交、文档/页面/会话切换、新手势或选择变化后的过时通知会被隔离。诊断保留未确认（未 ACK）姿态的汇总，不把未确认状态伪装为已经呈现。

已经结束的手势不适用自动接管。结束后才到达的失败必须拒绝，不能复活手势；本包不解决这类延迟捕获/迟到失败的主要耗时，也不能因此宣称当前全部故障已经修复。

这是失败后的编辑事务恢复，不是普通的降画质预览方案，也没有降低 GPU 采样或画质配置。它不保证后续手势的 native 快路径自动恢复：原有错误锁存可能使后续手势继续走 fallback。当前旋转闪烁、大表面工作集峰值或预算错误不在本修复范围；普通蓝框与真实画面的物理同帧，以及硬件画质/帧率仍未验收。

## 应用与撤回

需要 Git 和 Python 3。保存工作并停止并发编辑/构建，在解压后的包目录执行，替换为自己的 Core 绝对路径：

1. python3 apply_increment.py check /absolute/path/to/Core
2. python3 apply_increment.py apply /absolute/path/to/Core
3. 按项目既有流程重建并复现相同操作。应用源码不会更新已安装应用。

撤回：python3 apply_increment.py rollback /absolute/path/to/Core

check/apply 要求 HEAD 精确等于上述 146825d。本机源码或构建身份尚不确定、工作树字节不匹配时先停止核对，不能强行覆盖或据此推断是否装过其他修复。rollback 恢复本次 7 路径的 146825d 状态，不撤销已经进入该 Git 提交的上一包修复。rollback 不要求 HEAD 仍为基线，但仍严格要求受影响文件为精确旧/新字节。

所有模式都会先校验全部负载与目标文件，再写入；拒绝受影响路径的暂存修改、未知本地改动、符号链接或损坏负载。保留无关文件及暂存内容，不 checkout/reset，不改 Git 索引，不下载、不构建、不清理其他文件。单文件替换原子，多文件不是整体事务；中断后仅可在各文件仍为精确旧/新状态时重试或撤回。
