## 本轮内容

1. 维护显示模式误强制等待：显示输出模式本身不再被当作必须同步的理由；仅满足原有预算、水位、资源量、次数和完成边界约束的小型临时资源维护可以有限延后。所需分配、真实压力、退休图片资源和真实读回等必要等待不删除，不抬高预算，不提前释放或取消计费。
2. filter-table 资格顺序：在生成 dense 图片坐标场之前先检查 axes 资格，避免不适用的可选表路径先触发 64 MiB 原语限制。保留精确条带坐标，不降低采样质量；补足实际原语失败跨诊断边界的测试。这不是保证所有大图或分配失败都已消失。
3. 无预览支持的 fallback 提交：没有保留编辑预览可显示时直接向渲染面提交当前文档，不再多等一次 effect/timer。支持预览的路径仍保留原有合并提交安排。这不等于 GPU 已显示、蓝框与画面物理同帧，或 FPS 已提升。
4. Pose 生命周期诊断：增加有界标量来区分请求、完成、失败、拒绝与当前显示状态；本轮该部分是诊断，不新增未经验证的 fatal 异步自动回退功能。
5. 预算纹理分类诊断：最终分配失败时附带有界、不可变的资源分类快照，并保持原始失败归属。新增资源角色和请求来源帮助后续复现分析，不改变预算、回收、销毁或渲染策略。旧纹理缺少标签时如实记为未知；分类字节不是硬件 VRAM 实测，也不能仅凭它判定泄漏或可安全释放。

整面预算错误、fatal 异步自动回退、普通蓝框与真实画面的物理同帧问题仍未解决。预算快照字段需要重新复现才能取得，旧日志不能补出当时缺失的归属信息。详细字段边界见 source/docs/RENDER_SURFACE_BUDGET_SNAPSHOT_V1.md。

## 应用与撤回

需要 Git 和 Python 3。先保存工作并停止并发编辑/构建，在解压后的本包目录执行，使用你自己的 Core 绝对路径：

1. python3 apply_increment.py check /absolute/path/to/Core
2. python3 apply_increment.py apply /absolute/path/to/Core
3. 按项目既有流程重新构建并复现相同操作，保留新诊断日志。应用源码不会更新已安装应用。

撤回：python3 apply_increment.py rollback /absolute/path/to/Core

check/apply 必须匹配精确基线 HEAD；rollback 不要求 HEAD 仍为基线，但受影响文件仍必须是精确旧/新字节。全部操作拒绝受影响路径的暂存修改、符号链接、损坏负载或未知本地改动，保留无关工作区及暂存内容。不 checkout/reset，不修改 Git 索引，不下载、不构建、不清理其他文件。

单文件替换原子，多文件不是整体原子事务。中断后只在所有受影响文件仍为精确旧/新状态时重试或撤回。不要强制绕过保护，不要将旧包整文件覆盖到其他版本。
