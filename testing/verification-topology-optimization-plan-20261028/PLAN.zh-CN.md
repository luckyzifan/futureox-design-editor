# 拓扑真实文件：先测试再优化的实施计划

本轮范围是最新工作树的可复现基线、测试落地和修改方案，不提前修改渲染算法。输入为用户下载目录的 `拓扑素材.sketch`，只读打开；源码、原件与构建产物由 baseline/build manifest 绑定。历史性能数字不作为本轮结果。渲染规则见 [工程契约](../../docs/RENDERING_FIRST_ENGINEERING_CONTRACT.zh-CN.md)。

两轮测试已完成，修改顺序以 [本轮结果](RESULTS.zh-CN.md) 为准：局部视口先拆准备/编译，全览先减绘制调用，随后处理运动新密度与取消尾部。测试结束前又出现的常量覆盖opt-in/资源构造变更仅作静态复核，不冒充已测。

## 最新基线与已存在的能力

- 全源 Canvas 接线已经修复；`NativeSourceSurface` 已合入最多两瓦片的小批次与既有 PrepareAhead。
- 精确 DPR、最终相位、资源 ACK、局部失效、片段与覆盖缓存已存在，不重新实现。
- mixed solid、constant coverage、gradient fusion 等正在演进；本轮固定构建配置，不擅自开启默认关闭候选。
- 源文件全量、GPU 视口完成、最终 GUI 外观与全场景直接编辑是不同验收范围。

## 本轮测试先行

1. 冻结包含未提交文件的源码，重建实际 WASM/native/前端，在隔离 profile 中运行正式 native source Surface、原生导入与 WebGPU。记录 source drift，不追随测试期间的新修改。
2. 检查 Sketch 原件 SHA-256、ZIP 完整性与源目录；真实 largeDocument.open → canvasSnapshot → NativeSourceSurface，断言完整 306 个素材。源 hash 在测试后必须不变。
3. 固定 800×600 CSS 视口、实际 DPR、世界中心 (878,278)。覆盖 400% 冷首次/两次重建、3200%、全览、125% 分数相位与快速反向缩放返回。原生源载入与首块/完整呈现分别计时，冷数值单列。
4. 记录准备/编译、graph、checkpoint、finish、draw calls、像素工作分类、峰值字节、提前准备、取消、呈现密度及 rAF 停顿。阶段可能重叠，禁止简单求和。当前产物缺少的统计标 UNKNOWN，不补零。
5. 计时结束后读回实际 GPU 内容，核对相机、DPR、尺寸、非空内容；同视口重建/返回必须像素 hash 相同。保留 PNG 与隔离窗口截图。该 oracle 证明复用/取消一致，不能证明 Figma/Sketch 字形和效果已完全一致。
6. 测试自身提供负对照：旧相机、低分辨率、空白、部分源、CPU 后端、缺结果、并发失控和像素变化都必须拒收。失败和超时持久化；测试 timeout 仅为观测边界，不修改产品预算或任务期限。

本轮不设定事后可调整的“流畅”门槛。现有 UI stall >250ms 继续记录；输入到像素/停手时间缺乏正式目标，完整 G2 延迟门保持 BLOCKED。未来性能候选采用既有配对中位数至少改善 5% 的保留目标，精度与相关场景不得退化。

## 按证据选择的实现顺序

| 候选 | 逆向证据与当前落点 | 第一批修改 | 必须先有的测试 | 推广条件 |
|---|---|---|---|---|
| A 绘制/区域融合 | Figma effectPassFusion 的策略与拒绝原因；`gpu/renderer.ts` 已有严格快速路径 | 先归类实际最贵的 coverage/paint/merge/copy/effect 和拒绝原因，只扩展一个有精确证明的条件；保留四个相关样本、绘制顺序和原回退 | 原始 RGBA32F 逐位对照；非有限值、分数相位、裁剪/混合、资源撤销负例；真实拓扑固定视口配对 | 实际减少 draws 或处理面积，并改善真实端到端，不以合成测试代替 |
| B 几何展开前子树裁剪 | BIG-FILE-PIPELINE 的按需物化/不可见子树；`geometry_snapshot.rs` 常规文本轮廓在叶子离屏判断前 | 在 Rust 建立版本绑定的保守素材/子树光学边界，先筛选后展开；先离屏，再另做有限遮挡 | 同一完整源上固定可见内容，增加远处内容；应减少访问/展开节点，像素与未剪枝路径一致；阴影/描边/蒙版/backdrop 必须完整 | 全源局部视口编译和首块改善；全览不得丢对象、不能把布局提示当光学边界 |

| E 脏区空间合并 | 背景失效 SpatialPacking/BoundingUnion 遥测；`dirty_region.rs` 超过256矩形合成一个大框 | 保持原数量上界，合并增加面积最小的邻近区域，保留所有真实依赖 | 从真实拓扑选多个分散可编辑对象；257+矩形对照，变化像素全部覆盖，统计重绘面积/瓦片 | 用编辑场景证明收益，不冒充冷加载优化；完整源直接编辑未完成时该场景单列 |

## 每个候选的执行协议

先建立旧路径与独立负对照；只改一个变量；重建受影响产物；硬件同层精度通过后，再进行同设备交替 A/B，至少三对，保留冷启动与异常值。测量期间不安排本任务构建/重测试；记录其他进程竞争，不终止用户或其他任务进程。

优先顺序由本轮结果修订：graph/像素工作主导先 A；局部视口编译主导先 B；像素已便宜但等待和旧帧突出先 C。若 A 已由其他增量覆盖，则只验证当前命中和剩余缺口。每轮保存前置 hash、独立开关、回滚路径和未验门。

全 G5、117×10、600 图标导出、全部编辑/保存、device loss、跨平台与物理 scanout 不在本次基线 smoke 的通过声明内。

## 本轮实测后的首批修改拆分

以最终 RESULTS 中最新冻结轮为准。第一轮已明确区分两种瓶颈：400% 局部视口准备/编译主导；全览单个已交付瓦片有250074次绘制，300秒仍未完成视口。两者不使用同一种修法。

### 第一步：首块准备分段诊断与旧路径负对照

修改位置：Rust `renderer.rs::resolve_layout`、`gpu.rs::compile_gpu_scene`、`geometry_snapshot.rs::prepare_node_geometry`、`gpu/packet.rs`；沿现有 preparation/diagnostics 协议传少量数值字段。

先区分布局/派生准备、几何展开、节点编译、packet编码、传输/解码及暴露等待。现有 compileMs 是复合阶段，不能直接判定其中10秒都由几何造成。新增访问节点、文本整形、程序构建及稳定资源编码字节计数；不记录文档内容，也不在热路径同步写日志。

测试落点：以本目录真实入口为基座增加冷首块阶段表；冻结相同原件、视口、DPR和版本。计时字段缺失、重叠未说明、未真正进入生产路径时不出性能结论。得到热点后才在 B/D 中选一个修改。

### 第二步：全览专用的小图元批绘候选

修改位置：`gpu/scene_plan.rs` 的原顺序批次证明、`gpu/scene-index.ts` 的组能力判断、`gpu/renderer.ts` 的小区域 coverage/paint/merge/copy、`gpu/webgpu.ts` 的批次提交。

先统计全览真实拒绝原因，再选一个可证明的批次类型。首轮已看到混合纯色尝试多因证明条件失败，覆盖构建和合成调用很多；不能通过改变颜色管理、样本数或把小图元当作可忽略而减少它们。渐变融合/区域混合已经实际命中，需寻找剩余路径，不把已有命中当新成果。

测试落点：为选定类型建立 raw-f32 同层对照、非有限颜色/分数覆盖/叠放/背景依赖负例；然后跑完整拓扑全览。失败时保留部分已交付瓦片统计和取消前工作，不能把未完成请求的缺失数据补成0。先验证单块工作下降，再验证整个16块视口完成。

### 第三步：运动中的当前密度与后台尾部工作

修改位置：现有 `NativeSourceSurface`/Worker取消及呈现调度；普通 `ProgressiveSurface` 的导航预览另列测试，不能从 source Surface 推广。

先用本轮动作确定原生密度新像素是否真的在运动中出现；分别测首次有效完成、已完成后的后台请求清空和最终读回。返回旧视口命中缓存可以很快，但不能证明途中已达到3200%清晰。保存 maxUpscale、实际取消、回到相同视口的严格像素比较。

测试时将 readback/hash/截图/report 的开销单独标记。它们不参与渲染延迟或UI停顿归因；完成后的晚回也不能改写首次ready时间。对应的测试负对照已落在 report-contract.test.mjs。
