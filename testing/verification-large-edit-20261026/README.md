## 实际保留的修复

1. `InteractionRenderer.control.end`：鼠标释放时，尚未完成的首个整屏交互捕获也进入提交交接，不再等它完成/降为瓦片后才取消。只撤销该所有者的可选像素请求；已接受的文档修改和物理请求 fence 保留，晚成功像素正常释放，新手势可继续。
2. `ProgressiveSurface`：已有实际呈现、同文档 ID、同相机/尺寸/DPR/页面/会话/渲染策略/设备的旧画面时，提交修改后直接安排精确瓦片，省去一轮整屏低清预览。旧画面仍属于旧文档，不用于新内容完成判定或 ACK。相机、DPR、页面、会话、策略、文档或设备改变时保留原路径。
3. `KernelClient`：原生画布接收完整工作集替换时（pages 改变、补丁覆盖所有旧节点及所有新节点、新集合非空），使用现有完整同步建立真实原生源确认。旧路径已经发送全量节点，但结构性 bulk patch 无法续期属性补丁确认，交互随后又全量复制。普通局部编辑/追加仍用增量；没有放宽任何 receipt、CAS、null/undefined 或补丁大小保护。

旧代码负对照分别见 `release-old-failure.log` 和 `edit-priority-old-failure.log`；新实现通过同断言及取消/晚回、跨所有者和不同显示契约测试。
