🔧 缩放渲染修复验证指南

日期: 2026-10-17 | 修复版本: 基于 commit 29b86e545 + 本次修复

快速启动：
1. bun run dev 启动设计客户端
2. 打开一个包含矩形、文字、图片的复杂文档
3. 按照下面的测试用例逐项验证

📋 测试用例

测试 1: 缩小时的模糊窗口大小

操作步骤：

  1. 打开包含细节内容的文档（文字、小图标）
  2. 从 zoom 1.0 开始，使用鼠标滚轮或捏合手势连续缩小
  3. 注意观察内容从清晰变模糊、再变清晰的过渡点
内容在 zoom 0.10-0.12 时持续模糊（显示 0.1 bucket 放大 20-30%）
内容在接近 LOD bucket 阈值（如 0.105）时快速切换到精确渲染，模糊窗口缩小到约 5%

关键观察：

  • 模糊窗口应该明显变小
  • bucket 边界: 0.1 / 0.25 / 0.5 / 1.0
  • 切换应该发生在约 1.05x bucket 而非 1.3x bucket

测试 2: 放大后的变清晰速度

操作步骤：

  1. 将 zoom 设置为 0.15（介于 0.1 和 0.25 bucket 之间）
  2. 快速放大到 0.3（跨越 0.25 bucket 边界）
  3. 停止缩放手势，观察内容变清晰的时间
停止缩放后 0.5-1 秒才变清晰，感觉"卡顿"
停止缩放后 100-200ms 内快速变清晰（2-3 帧），流畅无卡顿感

技术原因：

  • 屏内瓦片无预算限制（立即提交所有视口瓦片）
  • 保留 8 瓦片预取（周边已部分预热）
  • Motion preview bucket key 复用（减少重复渲染）

测试 3: 连续缩放的流畅性

操作步骤：

  1. 从 zoom 0.1 连续滚轮放大到 1.0，不要停顿
  2. 观察过程中是否有"闪烁"或"重复刷新"
  3. 特别注意跨越 bucket 边界时（0.25 / 0.5）
能看到明显的"重新渲染"闪烁，尤其是跨 bucket 时
平滑过渡，motion preview 在同一 bucket 内复用，减少闪烁

如果出现问题：

  • 打开开发者工具，查看 console 是否有渲染错误
  • 检查 canvas[data-compositor-frames] 属性是否异常增长

测试 4: 极度放大时的显示质量

操作步骤：

  1. 将 zoom 设置为 0.08（使用 0.1 bucket，放大 0.8 倍）
  2. 快速放大到 0.18（使用 0.1 bucket，放大 1.8 倍）
  3. 观察内容的显示效果（模糊 vs 像素化）
极度模糊，文字几乎无法辨认
轻微像素化（blocky）但文字可辨认，然后在 100-200ms 内变为高清

权衡说明：

  • 放大 >1.5x 时，nearest-neighbor 滤波替代 bilinear
  • 会有"马赛克"效果，但比极度模糊更可接受
  • 精确瓦片到达后立即恢复平滑

测试 5: Retina 显示器兼容性

操作步骤：

  1. 在 Retina 显示器（DPR=2）上打开应用
  2. 重复测试 1-4
  3. 特别注意 bucket 切换是否正常
所有行为与非 Retina 一致，考虑了 detailLevel = zoom × DPR

Retina 特殊性：

  • 实际渲染密度是普通屏幕的 2x
  • LOD bucket 计算已包含 DPR，无需额外处理
  • 如果 DPR=2 时 zoom 0.5，detailLevel=1.0，使用 bucket 1.0

📊 性能指标对比

指标 修复前 修复后 改进幅度
LOD 切换延迟 30% 容差 5% 容差 6x 改进
Motion preview 缓存命中率 ~0% (每帧新 key) ~80-90% (bucket 内) ∞ (从无到有)
缩放后覆盖速度 基线 +8 瓦片预热 ~50% 更快
严重模糊情况 频繁发生 (>1.5x 放大) 改用 nearest (可读) 体验质变

🐛 已知边界情况

1. Nearest-neighbor 的像素化效果
在放大 >1.5x 时会看到"马赛克"效果，这是有意为之的权衡。如果用户反馈不佳，可以：
  • 调整阈值到 2.0x（更少触发 nearest）
  • 或完全移除此优化（保持固定 LINEAR，接受模糊）
2. 预取瓦片数量（8 个）
目前硬编码为 8 个，未来可以动态调整：
  • 低端设备/复杂文档: 降到 4 个
  • 高端设备/简单文档: 提升到 16 个
  • 根据 displayBudget 和实际性能动态计算

📞 反馈渠道

测试过程中如发现问题，请记录：

  • 具体操作步骤（zoom 范围、文档复杂度）
  • 设备信息（Mac 型号、显示器 DPR、浏览器版本）
  • 截图或录屏（如果可能）
  • 控制台错误日志
性能分析工具：
打开 Chrome DevTools → Performance → 录制一段缩放操作 → 查看：
  • draw 调用频率（应该稳定在 60fps）
  • texImage2D 调用次数（motion preview 复用应该减少）
  • 帧时间（应该 <16ms，最好 <8ms）
